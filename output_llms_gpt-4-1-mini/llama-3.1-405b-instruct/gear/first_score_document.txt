### 2. Correctness (30 points)

- **Body Creation:** `ChBodyEasyBox` and `ChBodyEasyCylinder` constructors do NOT take the system as the first argument. The correct signature is `(lengthX, lengthY, lengthZ, density, visualize, collision, material=None)`. Passing `sys` as first argument is incorrect and will cause runtime errors.  
- **Joints:** The revolute joints should be instances of `ChLinkLockRevolute()`, not `ChLinkRevolute()`. The latter is a base class or does not exist as per the documentation.  
- **Joint Initialization:** The frame passed to `Initialize` is `chrono.ChFrameD(chrono.ChVectorD(...))`. The documentation uses `chrono.ChCoordsysD(position, rotation)` or `chrono.ChFrameD` with position and rotation. Using only position is acceptable if rotation defaults to identity, but better to use `ChCoordsysD`.  
- **Gear Constraint:** `ChLinkGear.Initialize` takes two bodies, ratio, phase, and frame. The ratio is set to 2, phase 1, which may be intentional but not explained.  
- **Motor:** Uses `SetMotorFunction` which is not in the documentation; the correct method is `SetSpeedFunction`.  
- **Visualization:** Uses `app.AddLight(...)` with many parameters, but the documentation recommends `AddTypicalLights()` for standard lighting.  
- **Material Setting:** `GetVisualShape()` is not a standard method on `ChBodyEasy*` objects; visual assets are usually accessed via `GetAssets()`.  
- **Simulation Loop:** Uses `app.DoStep()` instead of `sys.DoStepDynamics()`. This is acceptable since `ChIrrApp` encapsulates the system stepping.  
- **Camera Position:** Uses `chronoirr.vector3df(0, 5, -10)` which is correct.  
- **Missing `app.Initialize()` call:** Required to initialize Irrlicht app before running.
