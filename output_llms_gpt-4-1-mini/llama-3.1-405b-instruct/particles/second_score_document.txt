### 2. Correctness (30 points)

- **Use of PyChrono API:**  
  The use of `ChBodyEasySphere` with a `ChContactMaterialNSC` passed as the last argument is **incorrect**. According to the API, `ChBodyEasySphere` expects density as the second argument, then booleans for visualization and collision, but **does not accept a material as an argument**. The material should be assigned separately to the collision model or contact material of the body, not passed in the constructor. This is a significant API misuse.  
- **Collision system retrieval:**  
  `coll = sys.GetCollisionSystem()` is called, but `GetCollisionSystem()` returns a collision system object, not necessarily a binding interface for visualization or collision. The usage of `self.coll.BindItem(body)` in the callback is suspicious because `BindItem` is not a documented method of the collision system. This likely will cause an error or is an incorrect API call.  
- **Force accumulation:**  
  The gravitational force calculation and application is logically correct and consistent with physics principles. ✔️  
- **Energy calculation:**  
  Kinetic energy uses `body.GetPos_dt().Length2()` which returns squared velocity magnitude, but kinetic energy formula requires velocity magnitude squared multiplied by 0.5 * mass. This is correct. ✔️  
- **Use of `body.EmptyAccumulators()`:**  
  This is a correct call to clear forces before accumulation. ✔️  
- **Use of `SetUseGyroTorque(False)`:**  
  This disables gyroscopic torque, which is acceptable but not explained. No error.  
- **Emitter particle creator:**  
  `ChRandomShapeCreatorSpheres` is used with diameter and density distributions, which is correct. ✔️  
- **Visualization binding:**

  `sys.SetSolverType(chrono.ChSolver.Type_PSOR)` is correct. ✔️
