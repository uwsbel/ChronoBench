### 2. Correctness (30 points)

- **Collision Shape Setup:**  
  The code uses `SetShape()` on bodies with `chrono.ChCollisionShapeBox(...)`. According to the API, collision shapes are not set this way. Instead, collision models should be built using `body.GetCollisionModel().AddBox(...)` and then `body.GetCollisionModel().BuildModel()`. Also, collision should be enabled explicitly with `body.EnableCollision(True)`.  
  Using `SetShape()` is not a valid method for collision shapes in PyChrono. This will cause the bodies to have no collision or incorrect collision behavior.  
  **Deduct 15 points** for incorrect collision shape setup.

- **Visual Shape Setup:**  
  The code uses `AddVisualShape(chrono.ChVisualShapeBox(...))`. The API expects visual shapes to be created with `chrono.ChVisualShapeBox(chrono.ChVector3d(...))` (i.e., a vector for size), but the code passes three separate floats. This is inconsistent with the documented usage.  
  Also, the visual shapes are added without color or material, which is acceptable but could be improved.  
  **Deduct 5 points** for minor inaccuracies in visual shape creation.

- **Body Mass and Inertia:**  
  Mass is set, but inertia tensors are not set. Without inertia, the simulation may behave unrealistically.  
  **Deduct 10 points** for logical error in body property setup.

- **Piston Fixed State:**  
  `piston.SetBodyFixed(False)` is called, but by default bodies are not fixed. This call is redundant but harmless.  
  **No deduction.**

  The crank joint frame uses `chrono.Q_from_AngAxis(chrono.CH_PI_2, chrono.ChVector3d(0,0,1))`, which is correct for a revolute joint aligned along the Z-axis. Other joints use `chrono.QUNIT`, which is identity quaternion, acceptable if the joint axis aligns with the bodies' frames.
