### 2. Correctness (30 points)

- **Imports:** `math` imported as `m`, used for `m.floor` - acceptable.
- **Constant PI:** Defined as `CH_PI = 3.1456` (incorrect value; actual π ≈ 3.14159). This is a minor numerical inaccuracy but could affect geometry calculations slightly. Deduct 5 points for minor inaccuracy.
- **Beam Section:**
  - `SetCircular(True)` and `SetDrawCircularRadius(beam_ro)` used instead of `SetAsCircularSection()`. Comment notes that `SetAsCircularSection()` would overwrite moments of inertia. This is acceptable and shows awareness.
- **Node Access:**
  - `builder.GetLastBeamNodes()` returns a list; `size()` method used which is a C++ method, not Python. In Python, `len()` should be used.
  - So, `builder.GetLastBeamNodes().size()` is incorrect and will raise an AttributeError.
  - Deduct 15 points for incorrect API usage that breaks code.
- **Joint Initialization:**
  - `ChLinkMateFix.Initialize(node_mid, mbodyflywheel)` is used. According to API, `Initialize(body1, body2)` expects two bodies, but `node_mid` is a node, not a body.
  - This is a logical error: joints connect bodies, not nodes.
  - Deduct 15 points for logical error.
- **Bearing Joint:**
  - `ChLinkMateGeneric(False, True, True, False, True, True)` initialized between `builder.GetLastBeamNodes().back()` (again, `.back()` is a C++ method, not Python) and `truss`.
  - Python equivalent should be `builder.GetLastBeamNodes()[-1]`.
  - Deduct 15 points for incorrect API usage.
- **Motor Joint:**
  - Initialized between `builder.GetLastBeamNodes().front()` (C++ method, not Python) and `truss`.
  - Should be `builder.GetLastBeamNodes()[0]`.
  - Deduct 15 points for incorrect API usage.
- **Motor Function:**
  - `rotmotor1.SetMotorFunction(f_ramp)` used, but API documentation shows `SetSpeedFunction()` as the method name.
  - Deduct 5 points for minor API misuse.
- **Visualization:**
  - Visualization of FEM mesh and glyphs is correctly set.
- **Solver:**
  - Pardiso MKL solver correctly set.
- **Simulation Loop:**
  - Correct usage.
