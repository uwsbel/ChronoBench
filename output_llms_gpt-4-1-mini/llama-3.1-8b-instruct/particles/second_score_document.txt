### 2. Correctness (30 points)

- **Collision Material Usage:**  
  `ChContactMaterialNSC` is created and passed to `ChBodyEasySphere`. According to the API, `ChBodyEasySphere` expects a `ChMaterialSurface` object, but `ChContactMaterialNSC` is not a subclass of `ChMaterialSurface`. The correct approach is to create a `ChMaterialSurfaceNSC` object for NSC systems.  
  **Deduct 15 points** for incorrect material usage that could affect collision behavior.

- **Particle Positioner Setup:**  
  `chrono.ChRandomParticlePositionOnGeometry()` is used with `chrono.ChBox(50, 50, 50)` and `chrono.ChFramed()`. However, `ChBox` is a geometry shape, but the API expects a `ChGeometry` object or a derived class. `ChBox` is a geometry, so this is acceptable. `ChFramed()` is a default frame, so this is fine.  
  **No deduction.**

- **Energy Calculation:**  
  - The kinetic energy calculation uses acceleration squared (`GetAcceleration().Length2()`), which is physically incorrect. Kinetic energy depends on velocity, not acceleration. It should use `GetPos_dt()` or `GetPos_dtdt()` for velocity or acceleration, but velocity is the correct quantity.  
  - Potential energy is computed using a modified gravitational constant and pairwise interactions, which is acceptable as a custom force.  
  - Forces are accumulated correctly on both bodies.  
  **Deduct 10 points** for logical error in kinetic energy calculation.

- **Use of `body.EmptyAccumulators()`:**  
  This is called every step for all bodies, which is correct to clear forces before the next step.  
  **No deduction.**

- **Solver Setup:**  
  Solver type set to PSOR with max iterations 40, which is acceptable.  
  **No deduction.**

- **Gravity Set to Zero:**  
  Gravity vector set to zero, presumably because custom gravity-like forces are applied. This is acceptable.  
  **No deduction.**

- **Particle Reservoir:**  
  `SetUseParticleReservoir(True)` and `SetParticleReservoirAmount(200)` are set, but the emitter is set to emit 2000 particles per second, which is more than the reservoir amount. This could cause emitter to run out of particles quickly. However, this is not necessarily incorrect but may cause unexpected behavior.  
  **No deduction.**

- **Callback Class:**  
  The callback disables gyro torque on bodies and binds them to visualization and collision systems, which is appropriate.  
  **No deduction.**
