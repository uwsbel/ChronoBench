### 2. Correctness (30 points)

- **Use of `SetAutomaticGravity(True, 2)`:**  
  According to PyChrono API, `SetAutomaticGravity` takes a boolean and an integer for direction index (0=x,1=y,2=z). Here, gravity is set to (0, -9.81, 0) on system, but mesh gravity is set with direction index 2 (z-axis). This is inconsistent because gravity vector is along y-axis, but mesh gravity is set to z-axis. This is a logical inconsistency and can cause unexpected behavior in FEM gravity application.

  **Deduct 10 points** for logical error in gravity setup.

- **Flywheel Creation:**  
  `ChBodyEasyCylinder` is called with `chrono.ChAxis_Y` as first argument. The API for `ChBodyEasyCylinder` expects radius, height, density, and optional visualize/collision/material parameters. The first argument being `chrono.ChAxis_Y` is incorrect usage. The correct call should be something like:

  ```python
  chrono.ChBodyEasyCylinder(radius, height, density, visualize=True, collision=True, material=None)
  ```

  The axis is not an argument here. To orient the cylinder, one should set the coordinate system accordingly.

  This is a **significant API misuse** that could cause errors or unexpected behavior.

  **Deduct 15 points** for incorrect API usage.

- **Joint Initialization:**  
  - `myjoint.Initialize(node_mid, mbodyflywheel)` uses a node and a body. The API expects two bodies or two ChPhysicsItem objects. A node is a `ChNodeFEAxyzrot` (FEA node), which is not a body. This is incorrect usage.

  - Similarly, `bearing.Initialize(builder.GetLastBeamNodes().back(), truss, chrono.ChFramed(...))` uses a node and a body. This is also incorrect.

  - `rotmotor1.Initialize(builder.GetLastBeamNodes().front(), truss, chrono.ChFramed(...))` same issue.

  Joints and motors should be initialized between bodies, not between nodes and bodies.

  This is a **major logical error**.

  **Deduct 15 points** for incorrect joint initialization.

- **Motor Function Setting:**  
  The motor function is set with `rotmotor1.SetMotorFunction(f_ramp)`. The API uses `SetSpeedFunction` for `ChLinkMotorRotationSpeed`. Using `SetMotorFunction` is incorrect or deprecated.

  **Deduct 10 points** for incorrect API call.

- **Use of `chrono.QuatFromAngleAxis`:**  
  Correct usage, no deduction.

- **Use of `chrono.ChVisualShapeFEA`:**  
  Correctly used for mesh visualization.

- **Solver Setup:**  
  MKL solver is correctly created and set.

- **Static Analysis:**  
  `sys.DoStaticLinear()` is valid.

- **Simulation Loop:**  
  Correct usage of visualization and stepping.
