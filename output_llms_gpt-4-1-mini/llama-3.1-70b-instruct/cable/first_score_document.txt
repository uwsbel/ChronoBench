### 2. Correctness (30 points)

- **Ground body creation:**

  ```python
  ground = chrono.ChBodyEasyBox(mysystem, 10, 1, 10, 1000, True, True)
  ```

  The documented constructor is:

  ```python
  ChBodyEasyBox(lengthX, lengthY, lengthZ, density, visualize, collision, material=None)
  ```

  The first argument should be lengthX, not the system. Passing `mysystem` as the first argument is incorrect.

  Deduct **15 points** for incorrect API usage that will cause runtime error or unexpected behavior.

- **Gravity setting:**

  Method name is `Set_G_acc()`, but the documented method is `Set_G_acc` or `Set_G_acceleration`? The documentation shows `Set_G_acc` is correct. No deduction.

- **Beam creation:**

  - `ChElementCableANCF` constructor does not take system, density, area, modulus, poisson, and two vectors directly.
  - In PyChrono, ANCF elements are usually created and added to a `fea.ChMesh()`, with nodes created separately.
  - The code incorrectly creates elements and adds them directly to the system.
  - Deduct **15 points** for incorrect use of ANCF elements API, which will prevent the beam from behaving as intended.

- **Adding elements to system:**

  - `mysystem.Add(element)` is incorrect for FEA elements; they should be added to a mesh, which is then added to the system.
  - Deduct **10 points** for logical error.

- **Hinge joint creation:**

  - `ChLinkHinge` constructor does not take arguments as shown.
  - The documented way is to create the link and then call `Initialize(body1, body2, frame)`.
  - Deduct **15 points** for incorrect joint initialization.

- **Visualization:**

  - Missing `AttachSystem()` and `Initialize()` calls.
  - Using `SetCamera()` instead of `AddCamera()` is a minor deviation.
  - Deduct **5 points** for minor inaccuracies in visualization API usage.
