### 2. Correctness (30 points)

- **API usage correctness:**  
  - `sys.SetGravitationalAcceleration(chrono.ChVector3d(0, -9.81, 0))` is correct.  
  - Ground body created with `chrono.ChBody()`, added with `sys.Add(ground)`. This is acceptable, though `sys.AddBody()` is more common and consistent with pendulum bodies. `sys.Add()` is an alias, so no issue.  
  - `ground.SetFixed(True)` and `EnableCollision(False)` are correct.  
  - Visualization shapes created with `chrono.ChVisualShapeCylinder(radius, height)` and added with `AddVisualShape()`. The frames used are `chrono.ChFramed(...)` which is deprecated or not standard; the API documentation specifies `chrono.ChCoordsysD` or `chrono.ChCoordsys` for frames.  
    - **Issue:** `chrono.ChFramed` is not part of the documented API; the correct class for frames is `chrono.ChCoordsys` or `chrono.ChCoordsysD`. Using `chrono.ChFramed` will likely cause an error or unexpected behavior.  
    - This is a significant API misuse.  
  - Similarly, `chrono.QuatFromAngleY(chrono.CH_PI_2)` is used, but the API documentation shows `chrono.ChQuaterniond` or `chrono.QuatFromAngleX/Y/Z`. This is acceptable if `QuatFromAngleY` exists.  
  - Joints are initialized with `chrono.ChFramed(...)` frames, which again is incorrect; should be `chrono.ChCoordsysD` or `chrono.ChCoordsys`.  
  - The joint frames for `rev_1` and `rev_2` use `chrono.ChQuaterniond(1,0,0,0)` which is a unit quaternion (w=1, x=0, y=0, z=0), so no rotation. This is correct.  
  - The joint frame for `rev_2` is at `(2,0,0)` relative to pend_1 and pend_2. Given pend_1 is at `(1,0,1)` and pend_2 at `(3,0,1)`, the joint frame at `(2,0,0)` seems inconsistent with the global positions. The joint frame should be specified in the coordinate system of the two bodies. Using `(2,0,0)` as a frame between pend_1 and pend_2 is likely incorrect; it should be at the connection point, e.g., `(2,0,1)` or relative to pend_1's frame.  
    - This is a logical error in joint initialization.  
  - The simulation loop and logging use correct API calls.  
  - `pend_1.GetPosDt()` is used to get linear velocity, which is correct.  
  - The timestep `1e-3` is reasonable.  

**Deductions:**  
- Incorrect use of `chrono.ChFramed` instead of `chrono.ChCoordsys` or `chrono.ChCoordsysD`: **-15 points** (significant API misuse).  
- Logical error in joint frame for `rev_2` (joint frame position inconsistent with pendulum positions): **-10 points**.
