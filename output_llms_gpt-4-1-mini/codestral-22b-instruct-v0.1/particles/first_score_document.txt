### 1. Completeness (40 points)

- **System Initialization:**

- **Body Creation:**  
  The script creates particles using `ChBodyEasySphere`, `ChBodyEasyBox`, and `ChBodyEasyCylinder`. However:  
  - For `ChBodyEasyBox` and `ChBodyEasyCylinder`, the constructor requires dimensions (lengths) as separate parameters, but the code calls them with a single scalar `1` (e.g., `chrono.ChBodyEasyBox(1, 1000, True, True)`). According to the API, `ChBodyEasyBox` requires lengthX, lengthY, lengthZ, density, visualize, collision, material. Similarly, `ChBodyEasyCylinder` requires radius, height, density, visualize, collision, material. The code passes only three parameters, which is incorrect.  
  - The sphere call is `shape(1, 1000, True, True)` which matches the API for `ChBodyEasySphere(radius, density, visualize, collision, material=None)`. So sphere is correct.  
  **Deduct 15 points for missing correct parameters for box and cylinder body creation.**

- **Force Model:**  
  A custom gravitational force class is created inheriting from `chrono.ChForce`. However, the PyChrono API does not document a `ChForce` base class with a `Compute` method returning a force vector. Forces are usually applied via `body.AddForce(chrono.ChVectorD(...))` or by creating force objects derived from `ChForce` with specific interfaces. The method `Compute` is not a recognized override in PyChrono for custom forces.  
  Also, the gravitational force calculation uses `-self.strength / self.body.GetPos().Length2() * self.body.GetPos()`, which is mathematically incorrect because `Length2()` returns the squared length, but the vector is not normalized before multiplication. The force should be proportional to the normalized vector divided by the square of the distance.  
  **Deduct 15 points for incorrect force model implementation and incorrect API usage.**

- **Adding Forces:**  
  The code iterates over `my_system.Get_bodylist()`. The correct method is `my_system.Get_bodylist()`, but in PyChrono, the method is `Get_bodylist()` returning a list or iterable of bodies. This is acceptable.  
  However, adding a force object (which is not a recognized force object) via `body.AddForce(force)` is incorrect because `AddForce` expects a `ChVectorD` force vector, not a force object.  
  **Deduct 15 points for incorrect force application.**
