### 2. Correctness (30 points)

- **Use of `ChContactMaterialNSC` in `ChBodyEasySphere`:**  
  The constructor for `ChBodyEasySphere` expects a material pointer for contact material. The code creates `sphere_mat = chrono.ChContactMaterialNSC()` and passes it to the constructor. However, according to PyChrono API, `ChBodyEasySphere` expects a `ChMaterialSurface` pointer, but `ChContactMaterialNSC` is a contact material, not a surface material. The correct approach is to create a `ChMaterialSurfaceNSC` (or SMC) and pass it to the body. This is a significant API misuse and can cause incorrect collision behavior.  
  **Deduct 15 points**

- **Setting friction on `ChContactMaterialNSC`:**  
  The friction is set on `sphere_mat` which is a `ChContactMaterialNSC`. This is not the correct way to set friction for a body’s surface material. The friction should be set on a `ChMaterialSurfaceNSC` object assigned to the body.  
  **Deduct 15 points** (combined with above, total 15 points deduction for material misuse)

- **Use of `SetUseGyroTorque(False)`:**  
  This is a valid call to disable gyro torque on the body. ✔️

- **Particle emitter configuration:**  
  The emitter is configured with random position, alignment, velocity, angular velocity, and shape creator distributions correctly. ✔️

- **Energy calculations:**  
  - Kinetic energy uses `body.GetPos_dt().Length2()` which returns squared velocity magnitude, but kinetic energy formula is `0.5 * m * v^2`. Since `Length2()` returns squared length, this is correct. ✔️  
  - Potential energy calculation uses a modified gravitational constant and pairwise summation over all bodies. ✔️  
  - No check for zero distance between bodies in potential energy calculation, which could cause division by zero if two bodies overlap exactly. This is a logical oversight.  
  **Deduct 10 points** for missing edge case handling in potential energy calculation.

- **Calling `body.EmptyAccumulators()` inside the loop:**  
  This is unnecessary because `DoStepDynamics()` internally manages forces and accumulators. It is not harmful but redundant.  
  **Deduct 5 points** for unnecessary API call.

- **Setting gravitational acceleration to zero:**  
  This is intentional for the simulation scenario. ✔️

- **Solver configuration:**  
  PSOR solver with 40 max iterations is set correctly. ✔️

**Correctness score: 30 - 15 - 10 - 5 = 0/30**
