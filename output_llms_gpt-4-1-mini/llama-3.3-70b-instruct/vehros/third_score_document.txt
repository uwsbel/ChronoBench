### 2. Correctness (30 points)

- **Box Body Not Added to System:**  
  As noted, the box is created but never added to the system. This will cause it to be ignored in simulation dynamics and collisions. This is a **significant correctness issue**.  
  **Deduct 15 points.**

- **Vehicle Initialization:**  
  The vehicle is initialized before setting visualization types. According to best practices and API, visualization types should be set **before** calling `Initialize()`. Setting visualization types after initialization may not have effect or cause inconsistencies.  
  **Deduct 10 points for incorrect order of visualization setup.**

- **Lidar Sensor Configuration:**  
  The lidar is set with `SetRange(0, 100)`. The API usually expects a minimum range > 0 (e.g., 0.1 or similar) to avoid invalid zero range. Setting min range to zero might cause issues or warnings.  
  This is a minor correctness issue.  
  **Deduct 5 points.**

- **Driver Inputs Synchronization:**  
  The code calls `driver.GetInputs()` before `driver.Synchronize(time)`. Usually, inputs should be updated after synchronization to get the latest inputs. This is a minor logical ordering issue but unlikely to cause major problems.  
  **Deduct 5 points.**

  `time_step` is assigned twice to `1e-3`. This is redundant but minor.  
  **Deduct 0 points here (covered under efficiency).**
