### 2. Correctness (30 points)

- **Mesh Loading and Transformation:**  
  - `LoadWavefrontMesh` is called with parameters `(filename, False, True)` which are `(load_normals, invert_normals)` according to typical API usage. This seems correct.  
  - `Transform` is called with position `(0,0,0)` and identity rotation matrix. This is acceptable but redundant since it does nothing. Minor inefficiency but not incorrect.  
  **No deduction.**

- **Body Properties:**  
  - `SetFixed(True)` and `SetMass(0)` are both called on static bodies. Setting mass to zero is redundant for fixed bodies but not incorrect.  
  - `ChBodyEasyBox` is created with parameters `(1,1,1,1000, False, False)` — the last two booleans are `visualize` and `collision`. Both are False, so the ground body has no visualization or collision. This is problematic because sensors are attached to this body, and it is fixed, but no collision or visualization is enabled.  
  - Usually, for sensor mounting, collision is not mandatory, but visualization is helpful. Lack of visualization on the ground body may reduce clarity.  
  - More importantly, the ground body is given angular velocity via `SetAngVelParent`. This is a valid API call, but applying angular velocity to a fixed body is questionable. Fixed bodies are immovable, so angular velocity will have no effect. This is a **logical error**.  
  **Deduct 10 points** for applying angular velocity to a fixed body (logical error).  
  - The correct approach would be to make the ground body non-fixed if it is to be moved or to apply angular velocity to a different body.

  - Noise models are correctly instantiated and passed.  
  **No deduction.**

  **No deduction.**
