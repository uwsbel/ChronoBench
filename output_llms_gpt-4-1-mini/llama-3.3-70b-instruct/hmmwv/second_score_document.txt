### 2. Correctness (30 points)

- **Vehicle Initialization**:  
  The vehicle is initialized correctly with contact method, collision type, tire model, and visualization types set before and after initialization appropriately.  
  **No deduction.**

- **Collision System Type**:  
  The collision system is set to `Type_BULLET` on the vehicle's system, which is correct and recommended for vehicle simulations.  
  **No deduction.**

- **Terrain Setup**:  
  The terrain patch is added correctly with friction and restitution set.  
  **No deduction.**

- **Visualization**:  
  The visualization system is correctly initialized and attached to the vehicle.  
  **No deduction.**

- **Path Following Logic**:  
  - The error calculation for steering uses the difference between the arctangent of the vector to the target point and the vehicle's yaw angle extracted via `vehicle_rot.EulerAngles().z()`.  
  - `EulerAngles()` returns a `ChVector` with angles in radians, but the order and convention can be ambiguous. The code assumes `.z()` is the yaw angle, which is typical in Chrono. This is acceptable but could be fragile if the rotation order changes.  
  - The steering input is set directly via `vehicle.GetPart(0).SetSteering(steering_input)`. However, `GetPart(0)` is ambiguous and not guaranteed to be the steering subsystem. The PyChrono Vehicle API typically provides methods like `vehicle.GetSteering()` or `vehicle.GetDriver()` to set inputs. Using `GetPart(0)` is fragile and may cause incorrect behavior if the part order changes.  
  - Similarly, throttle and braking inputs are set on `GetPart(0)`, which is likely incorrect. The vehicle API usually expects inputs to be set via a driver interface or specific methods.  
  **Deduct 15 points for incorrect use of vehicle input API that could significantly affect simulation behavior.**

- **PID Controller**:  
  The PID controller is implemented correctly and used properly.  
  **No deduction.**

- **Advancing Simulation**:  
  The vehicle, terrain, and visualization are advanced each step, which is correct.  
  **No deduction.**

- **Use of `AddCollide()` on balls**:  
  The method `AddCollide()` is called on the spheres, but according to the API, the method is `EnableCollision(True)` or `EnableCollisions(True)`. `AddCollide()` is not a documented method for `ChBodyEasySphere`. This could cause an error or be a no-op.  
  **Deduct 10 points for incorrect API usage on collision enabling for spheres.**
