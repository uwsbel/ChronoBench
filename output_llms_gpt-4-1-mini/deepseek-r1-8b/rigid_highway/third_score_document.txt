### 2. Correctness (30 points)

- **Use of PyChrono API:**  
  - The vehicle is created and configured correctly using the vehicle module API.  
  - Contact method and collision system type are set appropriately.  
  - Terrain patch is created with a contact material and mesh, consistent with vehicle examples.  
  - Visualization system is properly initialized and attached.  
  - Driver input deltas are calculated correctly based on render step size and response times.  
  - Simulation loop calls synchronization and advance methods in the correct order.  
  - Real-time timer is used properly to maintain real-time pacing.  

- **Potential issues:**  
  - `chrono.SetChronoDataPath(chrono.GetChronoDataPath())` is redundant but harmless.  
  - The terrain patch is added using a mesh file with a contact material for NSC contact. This is acceptable but the friction and restitution values are set on `ChContactMaterialNSC()`, which is correct for NSC contact method.  
  - The collision system type is set to `Type_BULLET` after vehicle initialization, which is acceptable but ideally should be set before initialization to ensure all collision models use the correct system. However, since the vehicle is initialized before setting the collision system type, this could cause inconsistent collision behavior or missed collision setup. This is a **significant correctness issue**.  
  - The vehicle's chassis collision type is set to `CollisionType_NONE`, which disables chassis collision. This is acceptable if intentional, but could affect simulation realism. No deduction since it is a valid choice.  
  - The `render_steps` calculation uses `math.ceil(render_step_size / step_size)`, which is correct.  
  - The `driver.GetInputs()` call is stored but not used directly; instead, `driver.Synchronize()` is called with time, and `vehicle.Synchronize()` is called with `driver_inputs`. This is consistent with the API.  
  - The `vis.Synchronize()` is called with `driver_inputs`, which is correct.  
  - The simulation loop does not call `sys.DoStepDynamics()` directly but advances each module separately, which is the recommended approach for vehicle simulations.  
  - The `terrain.AddPatch()` call uses a mesh file for the patch size parameter, which is acceptable for mesh-based terrain patches.  
  - The `patch.GetGroundBody().AddVisualShape()` is used to add a visual mesh, which is correct.  

**Deduction:**  
- Setting collision system type **after** vehicle initialization can cause issues with collision detection and is a significant correctness problem. Deduct **15 points**.
