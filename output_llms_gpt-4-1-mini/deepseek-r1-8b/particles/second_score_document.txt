### 2. Correctness (30 points)

- **Use of `ChContactMaterialNSC` in `ChBodyEasySphere`:**  
  The constructor expects a material pointer for contact material. The code creates `sphere_mat` as `ChContactMaterialNSC()` and passes it to `ChBodyEasySphere`.  
  **Issue:** According to PyChrono API, `ChBodyEasySphere` expects a `ChMaterialSurface` object, not a `ChContactMaterialNSC` (which is a contact material, not a surface material). The correct approach is to create a `ChMaterialSurfaceNSC()` object and set friction on it.  
  **Deduct 15 points** for incorrect material usage that can affect collision behavior.

- **Collision system retrieval:**  
  `coll = sys.GetCollisionSystem()` is called, but `GetCollisionSystem()` returns a pointer to the collision system, which is not typically used directly for binding items. The code uses `self.coll.BindItem(body)` in the callback.  
  **Issue:** The `BindItem` method is not documented for the collision system interface. Usually, bodies are added to the system and collision is handled internally. This may be a misuse or misunderstanding of the API.  
  **Deduct 10 points** for incorrect or unnecessary use of collision system binding.

- **`SetUseGyroTorque(False)` on bodies:**  
  This disables gyroscopic torque, which is acceptable but should be noted if intentional. No error here.

- **Particle emitter setup:**  
  The emitter uses `ChRandomParticlePositionOnGeometry()` with `ChBox(50, 50, 50)` and a default `ChFramed()`. This is acceptable.

- **Energy calculation:**  
  - Kinetic energy calculation is correct.  
  - Potential energy calculation uses inverse square law: `potential_energy -= G_constant * (m1*m2) / (r_attract ** 2)`  
  **Issue:** Gravitational potential energy should be proportional to `1/r`, not `1/r^2`. The force is proportional to `1/r^2`, but potential energy is proportional to `-G*m1*m2/r`.  
  This is a **logical error** in physics calculation.  
  **Deduct 10 points** for this logical error.

- **Clearing accumulators:**  
  The code calls `body.EmptyAccumulators()` for all bodies each step. This is unusual because PyChrono internally manages force accumulators during the step. Clearing them manually before stepping may interfere with force accumulation.  
  **Deduct 5 points** for a minor logical inaccuracy.

- **Solver settings:**  
  Solver type set to PSOR with 40 iterations is acceptable.

- **Gravity set to zero vector:**  
  Gravity is set to zero, which is consistent with the custom gravitational force implemented manually.

**Correctness score: 30 - 15 - 10 - 5 = 0/30**
