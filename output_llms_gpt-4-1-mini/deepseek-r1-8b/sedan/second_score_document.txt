### 2. Correctness (30 points)

- **Quaternion for vehicle2 rotation:**  
  The quaternion `(1, 0, 0, -1)` is used to represent a 180-degree rotation. Quaternions must be normalized to represent rotations correctly. The norm of this quaternion is `sqrt(1^2 + 0 + 0 + (-1)^2) = sqrt(2) ≈ 1.414`, which is not 1. This will cause incorrect orientation of the second vehicle. The correct quaternion for 180 degrees about the Z-axis is `(0, 0, 0, 1)` or `(0, 0, 1, 0)` depending on conventions, but definitely normalized.  
  **Deduct 15 points for incorrect use of quaternion leading to significant simulation behavior change.**

- **Use of `SetInitRotation` method:**  
  The API documentation and typical usage indicate that `SetInitPosition` takes a `chrono.ChCoordsysd` (position + rotation), but `SetInitRotation` is not a documented method for `veh.BMW_E90()`. The correct way to set initial rotation is via the `ChCoordsysd` passed to `SetInitPosition`. The code calls `vehicle2.SetInitRotation(...)` which is likely invalid or ignored.  
  **Deduct 15 points for incorrect API usage.**
