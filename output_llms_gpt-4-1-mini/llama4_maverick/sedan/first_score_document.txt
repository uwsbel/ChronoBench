### 2. Correctness (30 points)

- **Tire Parameter Retrieval Syntax:**  
  The line:  
  ```python
  tireParams = veh.TMeasyTire::GetTMeasyParams(28 * 0.9)
  ```  
  uses `::` which is invalid in Python. The correct call should be:  
  ```python
  tireParams = veh.TMeasyTire.GetTMeasyParams(28 * 0.9)
  ```  
  or possibly:  
  ```python
  tireParams = veh.TMeasyTire.GetTMeasyParams(28 * 0.9)
  ```  
  This syntax error will cause the script to fail.  
  **Deduct 15 points** for this critical API misuse.

- **Terrain Initialization Missing:**  
  As above, `terrain.Initialize()` is missing, which will cause the terrain patch not to be finalized and may cause simulation errors.  
  **Deduct 15 points** for this critical omission.

- **Driver Synchronization and Advance Order:**  
  In the simulation loop:  
  ```python
  vehicle.DoStepDynamics(1e-3)
  vis.BeginScene()
  vis.Render()
  vis.EndScene()
  driver.Synchronize(time)
  driver.Advance(1e-3)
  ```  
  The driver inputs should be synchronized **before** stepping the vehicle dynamics, and the driver should be advanced before the dynamics step to provide inputs for the next step. The typical order is:  
  ```python
  driver.Synchronize(time)
  driver.Advance(time_step)
  vehicle.ApplyInputs(driver.GetInputs())
  vehicle.DoStepDynamics(time_step)
  ```  
  Here, the driver is synchronized and advanced **after** the vehicle step, which is logically incorrect and can cause input lag or incorrect behavior.  
  **Deduct 10 points** for this logical error.

- **Use of `driver.GetInputs()` but no application:**  
  The code calls `driver.GetInputs()` but does not apply these inputs to the vehicle (e.g., `vehicle.GetDriveline().SetThrottle(...)` or similar). This is a logical error; the vehicle will not respond to driver inputs.  
  **Deduct 10 points** for this logical error.

- **Use of `chrono.Q_from_AngX` instead of documented `chrono.QUNIT` or `chrono.Q_from_AngX`?**  
  The code uses `chrono.Q_from_AngX(-math.pi / 2)` for terrain patch orientation, which is acceptable and consistent with API.

- **Use of `chrono.GetChOutputPath()` in vehicle constructor:**  
  The vehicle is constructed as:  
  ```python
  vehicle = veh.WheeledVehicle(chrono.GetChOutputPath() + "BMW_E90_sedan", veh.ChContactMethod_SMC)
  ```  

  This is unusual because `GetChOutputPath()` returns the output directory, not the data directory. Normally, vehicle models are loaded from the Chrono data path via `veh.GetDataFile(...)`. This may cause the vehicle to fail loading its model files.
