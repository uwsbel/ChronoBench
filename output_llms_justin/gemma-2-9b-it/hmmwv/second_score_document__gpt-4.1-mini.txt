### 2. Correctness (30 points)

- **Undefined Variable `render_steps`:**  
  This will cause a runtime error when the simulation loop tries to use it.  
  **Deduct 15 points** for incorrect use of API / variable leading to failure.

- **PID Controller Usage:**  
  The PID is created via `chrono.ChPID()`, parameters set, but the `Compute` method is called as `pid.Compute(error.x, time * step_size)`.  
  According to PyChrono API and general PID usage, `Compute` typically takes the current error and the current time (or delta time). Here, `time` is the simulation time, so multiplying by `step_size` is incorrect (time is already in seconds). Also, the error is a vector, but only `error.x` is used, which is a simplification but acceptable if the path is along x-axis.  
  However, the PID output is directly used as steering angle without any clamping or scaling, which may cause unrealistic steering commands.  
  **Deduct 10 points** for logical error / incomplete control logic.

- **Vehicle Access:**  
  The code uses `vehicle.GetVehicle().GetPos()` and `vehicle.GetVehicle().GetRot()`.  
  According to the vehicle API, `vehicle` is already a vehicle object, and `GetVehicle()` returns the underlying `ChVehicle` pointer. This is acceptable but somewhat redundant.  
  **Minor inaccuracy, no deduction.**

- **Setting Visualization Types:**  
  Visualization types are set after `Initialize()`. According to best practices, visualization types should be set **before** `Initialize()` to ensure proper setup.  
  **Deduct 10 points** for incorrect configuration order.

- **Setting Contact Method:**  
  The vehicle is set with `contact_method = chrono.ChContactMethod_NSC` and passed to `SetContactMethod()`. This is correct.

- **Setting Chassis Collision Type:**  
  Set to `veh.CollisionType_NONE`, which disables chassis collision. This is acceptable but may affect simulation realism. No deduction.

- **Sentinel and Target Spheres:**

- **Advance Calls:**
