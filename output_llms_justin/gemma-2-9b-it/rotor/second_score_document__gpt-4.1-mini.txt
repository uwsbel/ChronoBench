### 2. Correctness (30 points)

- **API Usage:**  
  - `mesh.SetAutomaticGravity(True, 2)` is used. According to PyChrono docs, this function enables gravity on the mesh nodes; the second argument is the direction index (0=x,1=y,2=z). Here it is set to 2 (z-axis), but the gravity vector is set as `(0, -3.71, 0)` which is along the y-axis. This is inconsistent and likely a logical error. Gravity direction index should match the gravity vector direction.  
  - The constant `CH_PI` is defined as 3.1456, which is inaccurate (should be 3.141592...). This can affect inertia and elasticity calculations.
  - `rotmotor1.SetMotorFunction(f_ramp)` is called, but the documentation indicates the method is `SetSpeedFunction()`. This is a significant API misuse and will cause the motor speed function not to be set correctly.
  - The `ChLinkMateGeneric` joint is initialized with `False, True, True, False, True, True` which corresponds to locking or freeing translation and rotation DOFs. This seems correct but should be double-checked for intended behavior.
  - The flywheel's coordinate system is set with `chrono.QuatFromAngleAxis(CH_PI / 2.0, chrono.VECT_Z)`. Given the inaccurate `CH_PI`, this rotation is slightly off.
  - The `sys.DoStaticLinear()` call is made before the simulation loop. This is unusual since the system is dynamic and the loop calls `DoStepDynamics()`. This call may be unnecessary or misplaced.
  - The `node_mid` is selected using `m.floor(builder.GetLastBeamNodes().size() / 2.0)`. The `size()` method is not standard Python; it should be `len()`. This will cause an error.
  - The `builder.GetLastBeamNodes()` returns a Python list or container; using `.size()` is incorrect.
  - The `chrono.ChVector3d` constructor is used correctly.
  - The `chrono.ChLinkMotorRotationSpeed` is initialized correctly except for the motor function method.
  - The visualization setup is correct.

**Major deductions:**

- 15 points for incorrect use of `SetMotorFunction` instead of `SetSpeedFunction`.
- 10 points for logical error in gravity direction mismatch between `SetAutomaticGravity` and `SetGravitationalAcceleration`.
- 10 points for use of `.size()` method on Python list (should be `len()`), which will cause runtime error.
- 5 points for inaccurate `CH_PI` constant affecting calculations.
- 5 points for unnecessary or misplaced `sys.DoStaticLinear()` call in a dynamic simulation.

Total deductions exceed 30, but max deduction for correctness is 30.
