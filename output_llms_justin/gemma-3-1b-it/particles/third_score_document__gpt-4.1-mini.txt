### 2. Correctness (30 points)

- **API Usage:** Mostly correct usage of PyChrono API.  
- **Logical Errors:**  
  - In the gravitational force calculation loop, variable names are inconsistent and cause errors:

    ```python
    f_attract = G_constant * (abodyA.GetMass() * abodyB.GetMass()) / (r_attract ** 2)
    F_attract = (D_attract / r_att) * f_att
    abodyA.AccumulateForce(F_att, abodyA.GetPos(), False)
    abodyB.AccumulateForce(-F_att, abodyB.GetPos(), False)
    ```

    Here, `r_att`, `f_att`, `F_att` are undefined variables. The correct variables are `r_attract`, `f_attract`, and `F_attract`. This is a critical error that will cause a runtime `NameError` and prevent the gravitational force from being applied.

  - The gravitational constant `G_constant` is set to `6.674e-3`, which is orders of magnitude larger than the real gravitational constant (~6.674e-11). While this might be intentional for simulation scale, it should be noted. Not necessarily an error but worth mentioning.

- **Force Application:** The force is applied at the body's position, which is correct.

- **Clearing Accumulators:** The code calls `body.EmptyAccumulators()` before force accumulation, which is correct.

- **Particle Emitter:** Properly emits particles each step.

**Deduction:**  
- 15 points for the critical variable naming error in gravitational force calculation that breaks simulation behavior.  
- No other major API misuse or logical errors.
