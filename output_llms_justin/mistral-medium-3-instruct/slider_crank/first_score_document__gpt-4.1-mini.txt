### 2. Correctness (30 points)

- **API Usage:**

  - `system.Set_G_acc(...)` is used instead of `system.Set_G_acc(...)` or `system.SetGravity(...)`. According to the documentation, the method to set gravity is `Set_G_acc()`. This is correct.

  - The motor joint uses `motor.SetMotorFunction(chrono.ChFunction_Const(1.0))`. The documentation specifies `motor.SetSpeedFunction(func)`. This is an incorrect API call and will likely cause an error or no effect. Deduct 15 points for incorrect API usage.

- **Joint Initialization:**

  - All joints are initialized with `chrono.ChCoordsysD(chrono.ChVectorD(...))` without specifying rotation. This defaults to identity rotation, which is acceptable if the joint axis aligns with the global axes. The crank is rotated by 90 degrees about X, so the revolute joint at the origin should have its axis aligned accordingly. The code does not specify rotation in the joint frames, which could cause misalignment of joint axes.

  - For example, the crank-ground revolute joint is initialized at (0,0,0) with no rotation frame specified. Since the crank is rotated by 90 degrees about X, the joint axis might not align with the crank's rotation axis. This is a logical error that can affect simulation behavior. Deduct 10 points for logical error in joint initialization.

- **Prismatic joint:**

  - The prismatic joint is initialized at the piston position with no rotation frame specified. The piston moves along the X-axis, so the prismatic joint axis should be aligned accordingly. Without specifying rotation, it defaults to identity, which aligns with X-axis, so this is correct.

- **Body Fixed Setting:**

  - The floor uses `SetBodyFixed(True)`. The documentation uses `SetFixed(True)`. This is an incorrect method name and will cause an error or no effect. Deduct 15 points for incorrect API usage.

- **Use of `SetPos` and `SetRot`:**

  - Correctly used.

- **Use of `app.DoStep()` in simulation loop:**

  - The documentation specifies `sys.DoStepDynamics(time_step)` or `app.DoStep()`. The code uses `app.DoStep()` without specifying a time step. This is acceptable as `app.DoStep()` internally advances the simulation by the fixed time step set in the Irrlicht app. No deduction.

**Correctness deductions:**

- 15 points for incorrect motor API call (`SetMotorFunction` instead of `SetSpeedFunction`).
- 15 points for incorrect `SetBodyFixed` method (should be `SetFixed`).
- 10 points for logical error in joint frame rotations (missing rotation in revolute joints where crank is rotated).
