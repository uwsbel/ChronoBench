### 2. Correctness (30 points)

- **Use of `ChContactMaterialNSC` in `ChBodyEasySphere`:** The constructor for `ChBodyEasySphere` expects a material pointer, but the API documentation shows `ChBodyEasySphere(radius, density, visualize, collision, material)`. The code passes `sphere_mat` which is a `ChContactMaterialNSC` instance. However, according to PyChrono API, `ChBodyEasySphere` expects a `ChMaterialSurface` or `ChMaterialSurfaceNSC` pointer, not a `ChContactMaterialNSC`. The latter is a contact material, not a surface material. This is a significant API misuse and will cause the material to be ignored or cause errors. **Deduct 15 points.**

- **Setting velocities with `SetPos_dt`:** Correct usage to set initial linear velocity. **No deduction.**

- **Force calculation and application:** The gravitational force is computed pairwise and applied correctly with `AccumulateForce`. However, the force magnitude `f_attract` is computed as positive scalar, and the direction vector is normalized and multiplied by this scalar. This is correct. The force is applied to both bodies with opposite signs, which is correct. **No deduction.**

- **Energy calculation:** Kinetic energy uses `velocity.Length2()`, which returns squared length, so kinetic energy is correctly computed as 0.5 * m * v². Potential energy uses `-G * m1 * m2 / r`. No check for zero distance (division by zero) is done, which could cause runtime errors if bodies overlap. This is a logical error. **Deduct 10 points.**

- **Use of `SetUseGyroTorque(False)`:** Called on bodies in the callback, but the callback is never registered or used. So this call has no effect. This is a minor correctness issue. **Deduct 5 points.**
