### 2. Correctness (30 points)

- **Collision System Type Setting:**  
  Setting collision system type after vehicle initialization may cause some components to initialize with default collision system, potentially leading to inconsistent collision behavior. According to best practices, this should be set before vehicle initialization.  
  **Significant issue: -15 points**

- **PID Controller Usage:**  
  The PID controller is created with gains `(1.0, 0.1, 0.01)` and used to update throttle input based on speed error. However, the `pid.Update(speed_error)` call is missing the time step parameter (usually required for PID update to compute integral and derivative terms properly). The PyChrono API for `ChPIDController` expects `Update(error, delta_time)`. Here, only one argument is passed. This will cause incorrect PID behavior.  
  **Significant API misuse: -15 points**

- **Driver Input Synchronization:**  
  The throttle input is set directly on `driver_inputs.throttle` after getting inputs from `driver.GetInputs()`. However, `driver_inputs` is a local copy, and modifying it may not affect the driver's internal state unless passed back or used properly. The script then calls `driver.Synchronize(time)`, but this does not update the driver's internal inputs with the modified throttle. The correct approach is to set inputs on the driver or use a custom driver class.  
  **Logical error: -10 points**

  The script uses `vehicle.GetVehicle()` to get the underlying vehicle object for mass and speed queries. This is correct according to the API.
