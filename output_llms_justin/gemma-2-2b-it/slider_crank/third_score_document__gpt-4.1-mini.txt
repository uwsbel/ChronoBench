  ```python
  ChBodyEasyCylinder(radius, height, density, visualize=True, collision=True, material=None)
  ```

  The first argument should be a float radius, but `chrono.ChAxis_Y` (an enum or vector) is passed instead. This will cause an error or unexpected behavior.

  This is a **significant API misuse** that can break the simulation or produce wrong geometry.

- **Motor joint initialization**: The motor is initialized with `chrono.ChFramed(crank_center)`. The API expects a `ChCoordsysD` (or `ChCoordsys`) for the frame, not `ChFramed`. `ChFramed` is not a standard PyChrono class; likely a typo or confusion with `ChCoordsys`. This will cause an error.

- **Joint initialization frames**: Similarly, `chrono.ChFramed` is used in joint initializations, which is not part of the documented API. The correct class is `chrono.ChCoordsysD` or `chrono.ChCoordsys`.

- **Motor speed function**: The motor speed function is created as `chrono.ChFunctionConst(chrono.CH_PI)`. The API uses `ChFunction_Const` (underscore), not `ChFunctionConst`. This is a naming error.

- **Getting motor angle**: `my_motor.GetMotorAngle()` is called. According to the API, `ChLinkMotorRotationSpeed` does not have `GetMotorAngle()` method; it has `GetMotorRotAngle()` or similar. This could be a logical error.

- **Closing visualization device**: The code calls `vis.GetDevice().closeDevice()` after 20 seconds. This is acceptable, but better practice is to break the loop or call `vis.Close()` if available.
