### 2. Correctness (30 points)

- **Use of `veh.ChBodyEasyBox`:**  
  The call is:  
  ```python
  box = veh.ChBodyEasyBox(chrono.ChVector3d(
      chrono.ChVector3d(random.uniform(-100, 100),
                        random.uniform(-100, 100), 0)
  ))
  ```  
  This is incorrect:  
  - `ChBodyEasyBox` expects dimensions (lengthX, lengthY, lengthZ), density, visualize, collision, material parameters, not a `ChVector3d`.  
  - The code passes a `ChVector3d` as the first argument, which is invalid and will cause runtime errors.  
  **Deduct 15 points for incorrect API usage that breaks simulation.**

- **Adding boxes every simulation step:**  
  This will cause the simulation to slow down and eventually crash or freeze due to unbounded body creation.  
  **Deduct 10 points for logical error.**

- **Sensor Manager creation and configuration inside the loop:**  
  The sensor manager should be created once outside the loop and updated inside. Creating and adding filters every step is incorrect and inefficient.  
  **Deduct 10 points for logical error.**

- **Use of `vis.AddLightDirectional()` instead of `AddTypicalLights()`:**  
  This is not incorrect per se, but less standard. Minor issue.  
  **Deduct 3 points for minor inaccuracy.**

- **`vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` is called after vehicle initialization:**  
  This is acceptable but usually collision system type is set before initialization. Minor issue but not critical.  
  **Deduct 3 points for minor inaccuracy.**
