### 2. Correctness (30 points)

- **Body Creation API Usage:**  
  - `chrono.ChBodyEasyBox(sys, 10, 1, 10, 1000, True, contact_material)`  
    According to the API, `ChBodyEasyBox` signature is:  
    `ChBodyEasyBox(lengthX, lengthY, lengthZ, density, visualize, collision, material)`  
    The first argument should be `lengthX` (float), not the system object. The system is not passed here.  
    Same for `ChBodyEasySphere`: the first argument should be radius (float), not system.  
  - This is a **significant API misuse** that will cause runtime errors or incorrect behavior.  
  **Deduction: 15 points** for incorrect API usage of body constructors.
- **Missing `sys.Add(body)` calls:**  
  - As noted above, bodies are not added to the system, so they won't be simulated.  
  **Deduction: Already counted under completeness.**
- **Link Initialization:**  
  - `link.Initialize(mass, ground, chrono.ChVectorD(0, 0, 0), chrono.ChVectorD(0, 0, 0))`  
  - According to the API, `ChLinkTSDA.Initialize` expects:  
    `Initialize(body1, body2, point1, point2)` where `point1` and `point2` are the attachment points in the **absolute coordinate system** or relative to the bodies.  
  - Using the same point for both ends (0,0,0) means zero-length spring, which is physically meaningless and likely a logical error.  
  **Deduction: 10 points** for logical error in joint initialization.
- **Visualization:**  
  - `vis.AddTypicalLights()` is called twice, which is redundant but minor.  
  - `vis.AddCamera(chrono.ChVectorD(0, 0, 5))` uses `ChVectorD` instead of `ChVector3d` (the API uses `ChVector3d`), but since `ChVectorD` is an alias for `ChVector3d`, this is minor.  
  - The visualization system is not attached to the system (already deducted).  
  - `vis.AddSphere` and `vis.AddLine` are used to add visual elements, but these are **not persistent visual shapes attached to bodies**; they are just one-time drawings that will not update with the simulation.  
  - Better practice is to add visual shapes to bodies or use the visualization system's standard rendering.  
  **Deduction: 5 points** minor inaccuracies in visualization usage.

- **Simulation Loop:** Correct usage. No deduction.
