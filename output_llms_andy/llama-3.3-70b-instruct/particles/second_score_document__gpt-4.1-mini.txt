### 2. Correctness (30 points)

- **Use of `ChContactMaterialNSC` in `ChBodyEasySphere`:**  
  The constructor for `ChBodyEasySphere` expects a material pointer or `None`. The code creates `sphere_mat` as `chrono.ChContactMaterialNSC()` and passes it as the last argument. According to the PyChrono API, `ChBodyEasySphere` expects a `ChMaterialSurface` pointer, but `ChContactMaterialNSC` is a material descriptor, not a surface material. The correct approach is to create a `ChMaterialSurfaceNSC` object and pass it. This is a **significant API misuse** that could affect collision behavior.  
  **Deduct 15 points.**

- **Collision system retrieval:**  
  `coll = sys.GetCollisionSystem()` is used, but the API documentation does not mention this method for direct collision system access. Usually, collision settings are done via system methods or collision models. However, since `coll` is used only for `BindItem` in the callback, and `BindItem` is not a documented method on collision system, this is suspicious. Possibly, `coll` is not the correct object to call `BindItem` on. This could cause runtime errors or undefined behavior.  
  **Deduct 15 points.**

- **Force accumulation and gravitational force calculation:**  
  The gravitational force is manually computed pairwise between bodies using Newton's law of gravitation. This is logically correct, but no check is done for zero distance (division by zero risk if two bodies coincide). This is a logical error in robustness.  
  **Deduct 10 points.**
