### 1. Completeness (40 points)

- **System Initialization:**  
  Present and correctly done with `chrono.ChSystemNSC()`. No deduction.

- **Body Creation:**  
  Bodies are created using `ChBodyEasySphere`. However, the constructor is incorrectly called:  
  ```python
  particle = chrono.ChBodyEasySphere(self.system, 0.1, 1000, True, pos)
  ```  
  According to the documentation, the signature is:  
  ```python
  ChBodyEasySphere(radius, density, visualize, collision, material=None)
  ```  
  The first argument should be the radius (float), not the system object. The system is not passed here. This is a **significant error** (see correctness below).  
  Also, `SetMass` and `SetInertiaXX` are called manually after creating the body with `ChBodyEasySphere`, which already sets mass and inertia based on density and radius. This is redundant and potentially conflicting.  
  Deduct **10 points** for incorrect body creation and missing proper material usage.

- **Visualization:**  
  Visualization system is created with `chronoirr.ChVisualSystemIrrlicht(mysystem)`. However, the documentation states that the visualizer should be created first and then attached to the system via `AttachSystem()`. The code passes the system in the constructor, which is not the documented usage.  
  Also, the visualizer is not initialized with `visualizer.Initialize()`. This is essential for setting up cameras and lighting.  
  The code sets camera position and window title but does not add typical lights or skybox, which are recommended for better visualization.  
  Deduct **15 points** for missing `Initialize()` and incorrect visualizer setup, and **5 points** for missing typical lights and skybox.

- **Force Application:**  
  The gravitational force is implemented as a custom force class `GravitationalForce` derived from `chrono.ChForce`. However, PyChrono does not document a `ChForce` base class with a `ComputeF` method. The standard way to apply forces is to use `particle.AddForce(chrono.ChVectorD(...))` or create custom force classes derived from `chrono.ChForce` with proper overrides. The method `ComputeF` is not a recognized override in PyChrono.  
  Also, the gravitational force calculation is a naive N-body gravitational force without any softening or cutoff, which can cause numerical instability or division by zero if particles are very close. No error handling for zero distance.  
  Deduct **15 points** for incorrect force implementation and missing robustness.
