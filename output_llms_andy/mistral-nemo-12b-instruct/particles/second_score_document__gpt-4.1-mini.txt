### 2. Correctness (30 points)

- **Use of API:**  
  - `ChSystemNSC` with BULLET collision is correct.  
  - `ChContactMaterialNSC` is correctly created and passed to `ChBodyEasySphere`.  
  - Visualization setup follows documented API.  
  - Particle emitter setup uses correct classes and methods.  
  - Solver type and iterations are set correctly.  
  - Simulation loop calls `vis.Run()`, `BeginScene()`, `Render()`, `EndScene()`, and `sys.DoStepDynamics()` properly.  

- **Logical errors:**  
  - **Energy calculation:**  
    - Kinetic energy calculation uses `velocity = body.GetPos().GetPos_dt()`. This is incorrect. `GetPos()` returns a `ChVector` position, which does not have `GetPos_dt()`. The velocity should be obtained by `body.GetPos_dt()` or `body.GetPos_dt()` directly. This is a significant logical error that will cause an AttributeError or incorrect results.  
    - Potential energy calculation is incorrect: it subtracts the gravitational force magnitude instead of gravitational potential energy. The gravitational potential energy between two masses is `-G * m1 * m2 / r`, but the code subtracts the force magnitude `f_attract`. This is a conceptual error in physics calculation.  
  - **Force application:**  
    - The gravitational force is computed and applied correctly as a vector force between bodies.  
  - **EmptyAccumulators:**  
    - Called on all bodies before force accumulation, which is correct.  
  - **Callback:**  
    - The callback class `MyCreatorForAll` inherits from `ChRandomShapeCreator_AddBodyCallback` and overrides `OnAddBody` correctly.  
  - **Particle emitter:**  
    - The emitter is configured properly and registered with the callback.  

- **API misuse:**  
  - `body.GetVisualShape(0).SetTexture(...)` is used correctly.  
  - `body.SetUseGyroTorque(False)` is a valid call.  
  - `sys.GetCollisionSystem()` returns the collision system; binding items to it is acceptable.  

**Deductions:**  
- **-15 points** for the incorrect velocity access (`body.GetPos().GetPos_dt()`), which is a significant API misuse and will cause runtime errors or incorrect kinetic energy.  
- **-10 points** for the incorrect potential energy calculation (using force magnitude instead of potential energy formula).  
- No other major API or logical errors detected.
