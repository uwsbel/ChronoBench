### 2. Correctness (30 points)

- **Incorrect use of `chrono.ChBodyEasy()`**:  
  As noted, `chrono.ChBodyEasy()` is not a valid constructor. The correct usage would be something like `chrono.ChBodyEasySphere(radius, density, visualize, collision, material)` or similar. This is a significant API misuse and will cause runtime errors.  
  **Deduct 15 points** for incorrect API usage.

- **Steering error calculation**:  
  The error is computed as `target_point.x - vehicle_pos.x`, which only considers the x-coordinate difference. For a 2D path (circle in XY plane), steering should consider lateral error (e.g., y-direction or cross-track error), not just x. This is a **logical error** in control logic.  
  **Deduct 10 points** for logical error in steering control.

- **Use of `vehicle.GetVehicle().GetMass()`**:  
  This is correct and consistent with the API.

- **Use of `vehicle.GetSystem().SetCollisionSystemType()`**:

- **Use of `veh.ChDriverInputs()`**:

- **Use of `vis.AddBody()` for path spheres**:  
  `vis.AddBody()` is not a documented method of `veh.ChWheeledVehicleVisualSystemIrrlicht()`. The visualization system typically attaches to the system or vehicle, not individual bodies. To visualize additional bodies, they should be added to the system and the visualization system should be attached to the system. This is a minor API misuse.  
  **Deduct 5 points** for minor API misuse.
