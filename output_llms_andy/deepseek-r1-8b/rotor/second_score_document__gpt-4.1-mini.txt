### 2. Correctness (30 points)

- **Use of `mesh.SetAutomaticGravity(True, 2)` and `sys.SetGravitationalAcceleration(...)`:**  
  The `SetAutomaticGravity` method is called with `True` and `2` as arguments. According to typical PyChrono usage, `SetAutomaticGravity` takes a boolean and an optional integer for the axis index (0=x,1=y,2=z). Here, gravity is set on axis 2 (z-axis), but then `sys.SetGravitationalAcceleration` sets gravity vector `(0, -3.71, 0)`, i.e., gravity along negative y-axis. This is inconsistent: gravity is set in two places with conflicting directions. This could cause confusion or unexpected behavior.

  **Deduct 15 points** for incorrect/conflicting gravity setup.

- **Use of `CH_PI = 3.1456`:**  
  The value of pi is incorrectly defined (should be 3.14159265...). This small error affects inertia and elasticity calculations. While minor, it affects correctness.

  **Deduct 5 points** for minor inaccuracy in constant definition.

- **Use of `pow(beam_ro, 4) - pow(beam_ri, 4)` in `SetJ`:**  
  The formula for polar moment of inertia J for a circular hollow section is correct. No deduction.

- **Joint Initialization:**  
  - `myjoint.Initialize(node_mid, mbodyflywheel)` is called without a frame argument. According to the documentation, `Initialize` requires two bodies and a frame (`chrono.ChCoordsysD`). Omitting the frame is incorrect and will cause an error or undefined behavior.

  **Deduct 15 points** for incorrect joint initialization.

- **`bearing = chrono.ChLinkMateGeneric(False, True, True, False, True, True)`**  
  The constructor arguments correspond to locking linear and angular degrees of freedom. The initialization uses `chrono.ChFramed(...)`, but `ChFramed` is not a documented class in the API; the correct class is `ChCoordsysD`. This is likely a typo or misuse.

  **Deduct 15 points** for incorrect API usage (`ChFramed` instead of `ChCoordsysD`).

- **Motor Initialization:**  
  `rotmotor1.Initialize(...)` uses `chrono.ChFramed(...)` again, which is incorrect.

  **Deduct 15 points** for same reason as above.

- **Motor Function:**  
  `rotmotor1.SetMotorFunction(f_ramp)` is called, but the documentation shows `SetSpeedFunction`. This is a naming inconsistency. The correct method is `SetSpeedFunction`.

  **Deduct 10 points** for incorrect method name.

- **Use of `m.floor(builder.GetLastBeamNodes().size() / 2.0)`:**  
  `builder.GetLastBeamNodes()` returns a Python list, which uses `len()` for size, not `.size()`. This will cause an error.

  **Deduct 15 points** for incorrect list size usage.

- **`sys.DoStaticLinear()` call:**  
  This method is used for static linear analysis. It is acceptable but usually requires proper static solver setup. No explicit solver settings for static analysis are shown, but MKL solver is set. No deduction.
