### 2. Correctness (30 points)

- **AddRandomBoxes function**:  
  - The function uses `while True` with no break condition except inside the `else` clause, which is only triggered if the box position is inside a certain range. This logic is flawed and will likely cause an infinite loop or no boxes added.  
  - The calculation of `box_pos` uses `(2 * (range(100, 200)))` which is invalid Python: `range` returns an iterable, and multiplying by 2 is nonsensical here. This is a critical error that will cause runtime exceptions.  
  - The call `veh.ChBodyEasyBox(box_size, box_pos)` is incorrect: `ChBodyEasyBox` expects dimensions as separate floats, density, visualize, collision, and material parameters, not a vector and position. Also, the position should be set via `SetPos()`, not passed as an argument.  
  - The box is added to the system via `vehicle.GetSystem().AddBody(box)`, which is correct if the box is properly created.

  **Deduct 15 points** for this critical misuse of API and logic errors.

- **Vehicle Initialization**:  
  - `vehicle.SetContactMethod(contact_method)` is called before `vehicle.Initialize()`, which is correct.  
  - `vehicle.SetChassisCollisionType(chassis_collision_type)` is set properly.  
  - `vehicle.SetTireStepSize(tire_step_size)` is set, which is good.  
  - `vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` is called after initialization, which is acceptable but better to set before initialization to ensure proper setup.  
  **Deduct 5 points** for suboptimal ordering.

  **Deduct 15 points** for critical API misuse.

- **Simulation Loop**:  
  - The loop uses `vis.Run()` correctly.  
  - The synchronization and advance calls are in correct order.

- **Miscellaneous**:
