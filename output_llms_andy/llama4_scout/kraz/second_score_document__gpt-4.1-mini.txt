### 2. Correctness (30 points)

- **Use of `veh.Kraz()` and system:**  
  Correct usage; the vehicle module handles system internally.

- **Setting contact method and collision system:**  
  `vehicle.SetContactMethod(contact_method)` and `vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` are correctly used.

- **Chassis collision type:**  
  Set to `veh.CollisionType_NONE`, which disables chassis collision. This is acceptable if intentional (e.g., for performance or specific simulation needs). No error here.

- **Visualization types:**  
  The calls to `SetChassisVisualizationType`, `SetSteeringVisualizationType`, etc., use `vis_type` consistently.

- **Terrain material:**  
  `chrono.ChContactMaterialNSC()` is used with friction and restitution set. No damping or compliance set, but for NSC this is acceptable.

- **Driver input modification:**  
  The code modifies `driver_inputs.steering` directly, which is allowed. However, the code calls `driver.GetInputs()` once per loop, modifies the steering, but does not call `driver.SetInputs()` or similar. In the PyChrono vehicle API, the interactive driver typically manages inputs internally, and direct modification of `driver_inputs` may not propagate correctly. This is a **logical error**: modifying the returned inputs object does not affect the driver's internal state unless explicitly set back or the driver is designed to accept this pattern.  
  **Deduct 10 points for logical error in driver input handling.**

- **Visualization attachment:**  
  The visualization attaches `vehicle.GetTractor()`. This is correct because `veh.Kraz()` returns a vehicle wrapper with `GetTractor()` returning the underlying `ChWheeledVehicle` instance.

- **Step size consistency:**  
  Step size is set to 1e-3, render step size to 1/50, and render steps computed accordingly. This is correct.

- **Use of `vehicle.Advance()`, `terrain.Advance()`, `driver.Advance()`, and `vis.Advance()`:**  
  Correct usage.

- **Use of `realtime_timer.Spin(step_size)`:**  
  Correct for pacing the simulation.

- **Minor issue:**  
  The line `chrono.SetChronoDataPath(chrono.GetChronoDataPath())` is redundant and unnecessary since it sets the data path to itself. This is minor but unnecessary.  
  **Deduct 5 points for minor unnecessary API call.**
