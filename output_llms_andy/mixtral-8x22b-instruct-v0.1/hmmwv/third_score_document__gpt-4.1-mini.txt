### 2. Correctness (30 points)

- **API usage correctness:**  
  - The vehicle is created and configured correctly with contact method, collision type, tire model, and visualization types.  
  - Terrain patch is created with NSC contact material and proper friction/restitution.  
  - Visualization system is correctly initialized and attached to the vehicle.  
  - Driver class correctly inherits from `veh.ChDriver` and overrides `Synchronize`.  
  - Driver input deltas are set properly based on render step size.  
  - Simulation loop uses `vis.Run()` as loop condition, and calls `BeginScene()`, `Render()`, `EndScene()` at correct intervals.  
  - Synchronize and Advance calls are in correct order and include all components.  
  - Real-time timer is used correctly.

- **Potential issues:**  
  - In the driver `Synchronize` method, `m_steer`, `m_throttle`, and `m_braking` are set, but `m_steer` is not initialized in the first `if` block (time < delay). This could lead to undefined behavior if `m_steer` is used before assignment. However, since `m_steer` is set in later blocks, and the driver is initialized before simulation, this is a minor logical issue.  
  - The sinusoidal steering and braking inputs use `math.sin(time - 2)` but the time window is from 0 to 4 seconds, so the argument to sin can be negative or positive; this is acceptable but might cause unexpected behavior in braking (negative braking values). Braking should be clamped to [0,1] or non-negative. The code does not clamp braking input, which could cause logical errors in the simulation.  
  - The vehicle's system collision type is set after vehicle initialization. According to best practices, collision system type should be set before initialization to ensure proper setup. This is a significant correctness issue.

**Deduction:**  
- 15 points for setting collision system type after vehicle initialization (significant impact).  
- 10 points for logical error in driver braking input potentially being negative (logical error).  
- 5 points for missing initialization of `m_steer` in the first driver `Synchronize` block (minor inaccuracy).
