### 2. Correctness (30 points)

- **Collision Model Setup for Bodies:**  
  For `box` and `cylinder`, the collision model is cleared and rebuilt with shapes and materials. However, the calls to `AddBox` and `AddCylinder` use two `ChVectorD` arguments as if defining two corners of a box or cylinder. According to the API, `AddBox` expects a material and a half-dimension vector (centered box), and `AddCylinder` expects a material, radius, and height or two points defining the axis. The usage here is incorrect:

  ```python
  box.GetCollisionModel().AddBox(box_mat, chrono.ChVectorD(-0.5, -0.5, -0.5), chrono.ChVectorD(0.5, 0.5, 0.5))
  ```
  This is not the correct signature. The correct usage is:

  ```python
  box.GetCollisionModel().AddBox(box_mat, 0.5, 0.5, 0.5)
  ```
  Similarly for cylinder, the `AddCylinder` call is incorrect:

  ```python
  cylinder.GetCollisionModel().AddCylinder(cylinder_mat, chrono.ChVectorD(-0.5, -0.5, -0.5), chrono.ChVectorD(0.5, 0.5, 0.5))
  ```
  The API expects radius and height or axis points, but these vectors do not define a cylinder axis properly.

  This misuse could cause collision shapes to be incorrectly defined or ignored, significantly affecting simulation behavior.

  **Deduct 15 points for incorrect collision model API usage.**
