### 2. Correctness (30 points)

- **System and Gravity:** Correct use of `ChSystemNSC` and gravity vector.  
- **Terrain and Material:** Correct use of `veh.RigidTerrain` and `ChMaterialSurfaceNSC`.  
- **Patch Creation:** The call to `AddPatch` uses `chrono.ChCoordsysD()` as first argument, then two floats (100, 100), then material. According to the API, `AddPatch` signature is usually `(material, coordsys, length_x, length_y)`. Here, the order is swapped: the code passes coordsys first, then lengths, then material. This is incorrect. The correct call should be:

  ```python
  patch = terrain.AddPatch(patch_mat, chrono.ChCoordsysD(), 100, 100)
  ```

  So the order of arguments is wrong, which could cause an error or unexpected behavior.

  **Deduct 15 points for incorrect API usage that could affect simulation behavior.**

- **Material friction set after patch creation:** This is acceptable; the material is created first, then friction set, then passed to patch. However, in the code, the patch is created with `patch_mat` before friction is set on `patch_mat`. This means the patch material might not have friction set at the time of creation. Usually, the material should be fully configured before being passed to `AddPatch`. This is a minor correctness issue.

  **Deduct 5 points for minor inaccuracy in material setup timing.**

- **Vehicle Initialization:** The vehicle is initialized with `veh.ChContactMethod.NSC` and `True` for some boolean (probably for visualization). This matches the API.  
- **Driver and Visualization:** Correct usage.  
- **Simulation Loop:** Correct synchronization and stepping.  
- **Camera Setup:** The camera is set with `SetChaseDirection(irr.VECT_Y, True)`. According to the API, `SetChaseDirection` expects a vector and a boolean for inverted direction. Using `irr.VECT_Y` is correct for chase direction along Y.  
- **Texture Application:** The texture is applied to the patch's visual material with scaling parameters (200, 200), which is acceptable.  
- **Time Step:** Fixed at 0.01 seconds, reasonable for vehicle simulation.
