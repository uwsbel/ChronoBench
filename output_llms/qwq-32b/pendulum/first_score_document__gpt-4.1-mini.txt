### 1. Completeness (40 points)

- **System Initialization:**  
  Present and correctly done with `chrono.ChSystemNSC()`.

- **Gravity Setting:**  
  Uses `system.Set_G_acc(chrono.ChVectorD(0, -9.81, 0))`.  
  According to the API, the method is `Set_G_acc` (underscore), which is correct.  
  **No deduction.**

- **Body Creation:**  
  - Ground body created with `chrono.ChBody()`, fixed, positioned, collision model added, and visual asset added.  
  - Pendulum body created with mass, inertia, collision model, and visual asset.  
  **No deduction.**

- **Collision Model Setup:**  
  Collision shapes added and `BuildModel()` called for both bodies.  
  However, **collision is never enabled explicitly** via `EnableCollision(True)`. According to best practices, after setting collision models, one should call `EnableCollision(True)` on the bodies to activate collision detection. This is missing.  
  **Deduct 10 points** (component present but lacks important detail).

- **Joint Creation:**  
  Uses `chrono.ChLinkRevolute()`.  
  According to the API, the revolute joint class is `ChLinkLockRevolute()`. The script uses `ChLinkRevolute()`, which is **not a documented class** in the API. This is a significant error.  
  **Deduct 15 points** (incorrect API usage).

- **Joint Initialization:**  
  The joint is initialized with `joint.Initialize(ground, pendulum, chrono.ChFrameD(...))` and then `SetAxis(...)` is called.  
  The API for revolute joints (`ChLinkLockRevolute`) does not have a separate `SetAxis()` method; the axis is defined by the frame passed to `Initialize()`. Using `SetAxis()` on a joint that does not support it is incorrect.  
  **Deduct 10 points** (logical error in joint initialization).

- **Adding Bodies and Joint to System:**  
  Bodies and joint are added to the system properly.  
  **No deduction.**

- **Visualization Setup:**  
  Uses `chronoirr.ChIrrApp` instead of the recommended `chronoirr.ChVisualSystemIrrlicht()`.  
  The API documentation suggests using `ChVisualSystemIrrlicht` for visualization, attaching the system, setting window size, title, initializing, adding camera, lights, etc.  
  `ChIrrApp` is a higher-level helper class but is not documented here. While it is part of PyChrono, the documentation does not mention it, so this is a minor deviation.  
  **Deduct 5 points** (minor omission/deviation).

- **Visualization Configuration:**  
  Adds typical lights and camera, binds and updates assets, sets timestep.  
  **No deduction.**

- **Simulation Loop:**  
  Uses `app.GetDevice().run()` for loop control, which is consistent with Irrlicht usage.  
  Calls `BeginScene()`, `DrawAll()`, `DoStepDynamics()`, and `EndScene()`.  
  However, the API documentation suggests `DoStepDynamics(time_step)` with explicit timestep argument, but here `DoStepDynamics()` is called without arguments. This might be acceptable if the timestep is set elsewhere, but the API example shows timestep passed explicitly.  
  The timestep is set via `app.SetTimestep(0.005)`, so this might be acceptable.  
  **No deduction.**

- **Data Printing:**  
  Prints position and velocity every 0.1 seconds using modulo and `app.GetSystem().GetStep()`.  
  This is a clever approach but could be slightly fragile due to floating-point modulo.  
  **No deduction.**
