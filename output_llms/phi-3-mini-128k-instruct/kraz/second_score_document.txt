### 2. Correctness (30 points)

- **Use of `vehicle.SetChassisVisualizationType(vis_type, vis_type)` and similar calls:**  
  The method `SetChassisVisualizationType` takes one argument (type), but here two arguments are passed. According to the PyChrono vehicle API, these methods usually take a single visualization type argument. This is likely an error or misuse.  
  **Deduct 15 points** for incorrect API usage that could cause runtime errors or unexpected behavior.

- **`vis.AttachVehicle(vehicle.GetTractor())`:**  
  The vehicle is created as `veh.Kraz()`. The method `GetTractor()` is called on the vehicle to attach it to the visualization. However, `veh.Kraz()` does not have a `GetTractor()` method. The correct method to get the vehicle chassis is `vehicle.GetVehicle()` or simply `vehicle`. This is a logical error that will cause an AttributeError at runtime.  
  **Deduct 15 points** for this significant logical error.

- **Driver inputs modification after `driver.GetInputs()`:**  
  The code modifies `driver_inputs.steering`, `driver_inputs.throttle`, and `driver_inputs.braking` directly after getting the inputs. However, `driver.GetInputs()` returns a copy or a reference that may not affect the driver's internal state. The proper way is to use `driver.SetInput()` or to control the driver via its API. This could cause the lane change maneuver to not work as intended.  
  **Deduct 10 points** for logical error in driver input handling.
