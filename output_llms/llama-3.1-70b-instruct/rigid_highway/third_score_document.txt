### 2. Correctness (30 points)

- **Use of `chrono.SetChronoDataPath(chrono.GetChronoDataPath())`:**  
  This call is redundant and does nothing effectively. It should be set to an explicit path or omitted if already set externally.  
  **Minor correctness issue, -5 points.**

- **Terrain patch creation:**  
  The patch is created with a mesh collision shape from `'vehicle/terrain/meshes/Highway_col.obj'` and visualization mesh from `'terrain/meshes/Highway_vis.obj'`. The position and orientation of the patch use `chrono.Q_from_AngZ(-math.pi/2)`.  
  However, the API documentation shows `chrono.QUNIT` or `chrono.Q_from_AngZ` (note the capitalization difference). The script uses `chrono.Q_from_AngZ` which is not consistent with documented `chrono.QuatFromAngleZ`.  
  Actually, the script uses `chrono.Q_from_AngZ` in the patch creation line, but earlier uses `chrono.QuatFromAngleZ` for `initRot`. This inconsistency suggests a typo or incorrect function name.  
  According to the API, the correct function is `chrono.QuatFromAngleZ(angle)`.  
  **Incorrect API usage, -15 points.**

  The vehicle is set with chassis collision type `veh.CollisionType_NONE`. This disables chassis collision, which is acceptable but may affect simulation realism. No error here, but a design choice.  
  **No deduction.**

- **Collision system type:**

  **No deduction.**

- **Driver input deltas:**

- **Simulation loop:**

- **Use of `vehicle.GetVehicle().GetMass()` for printing vehicle mass:**
