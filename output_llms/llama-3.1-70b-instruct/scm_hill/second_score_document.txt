### 2. Correctness (30 points)

- **`chrono.SetChronoDataPath(chrono.GetChronoDataPath())`**:  
  This line sets the data path to itself, which is redundant but harmless. Usually, the user should set the path explicitly. Minor inefficiency but no error.  
  **No deduction.**

- **Vehicle Initialization**:  
  - `vehicle.SetContactMethod(contact_method)` with `chrono.ChContactMethod_SMC` is consistent with SCM terrain.  
  - `vehicle.SetChassisCollisionType(veh.CollisionType_NONE)` disables chassis collision, which is acceptable for this demo.  
  - Visualization types are set after initialization, which is allowed.  
  - `vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` is set after vehicle initialization, which is acceptable but ideally should be set before adding bodies to the system for consistency. Minor issue but no significant impact.  
  **No deduction.**

- **Terrain Initialization**:  
  - `terrain.Initialize()` is called with height map and mesh resolution parameters. The parameters `-1,1,0.02` correspond to height scaling and mesh spacing. This matches typical usage.  
  - `terrain.AddMovingPatch()` is used correctly.  
  - Soil parameters are reasonable.  
  **No deduction.**

- **Obstacles Creation**:  
  - `chrono.ChBodyEasyBox(vehicle.GetSystem(), 1, 1, 1, 1000)` is incorrect usage. According to the API, `ChBodyEasyBox` constructor signature is:  
    ```python
    ChBodyEasyBox(lengthX, lengthY, lengthZ, density, visualize=True, collision=True, material=None)
    ```  
    The first argument should be lengthX, not the system. The system is not an argument here.  
  - The correct way is:  
    ```python
    obstacle = chrono.ChBodyEasyBox(1, 1, 1, 1000)
    ```  
  - Then, `vehicle.GetSystem().Add(obstacle)` adds the obstacle to the system.  
  - So, passing `vehicle.GetSystem()` as the first argument is a significant API misuse that will cause an error or unexpected behavior.  
  **Deduct 15 points for incorrect API usage here.**

- **Lidar Sensor Setup**:  
  - `ChLidarSensor` constructor is called with `(vehicle.GetChassisBody(), chrono.ChVectorD(0,0,2), chrono.ChVectorD(0,0,1))`. The last argument is the direction vector; this is correct.  
  - Frequency, range, FOV, resolution, visualization, and filters are set properly.  
  **No deduction.**

- **Simulation Loop**:  
  - The loop uses `vis.Run()` as condition, which is standard.  
  - Rendering is done every `render_steps` steps, which is correct.  
  - Synchronize and advance calls are in correct order.  
  - `realtime_timer.Spin(step_size)` is used for real-time pacing.  
  **No deduction.**

- **Minor logical issue**:  
  - The variable `render_step_size` is set as `1.0 / 20` with comment `FPS = 50`. This is inconsistent: 1/20 = 0.05s per frame = 20 FPS, not 50 FPS.  
  - This is a minor comment error, not affecting code correctness.  
  **Deduct 5 points for minor inaccuracy in comment/documentation.**

**Correctness score: 30 - 15 - 5 = 10/30**
