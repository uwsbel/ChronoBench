### 2. Correctness (30 points)

- **Critical error: Shadowing the `sys` module**  
  The code imports `sys` (Python standard library) at the top:  
  ```python
  import sys
  ```  
  Then immediately overwrites it with:  
  ```python
  sys = chrono.ChSystemNSC()
  ```  
  This shadows the `sys` module, which is a bad practice and can cause confusion or errors if `sys` module functions are needed later. Although the code does not use `sys` module functions later, this is a **significant correctness issue** because it breaks standard Python conventions and can cause bugs in larger scripts.  
  Deduct **15 points** for this.

- **Incorrect use of `chrono.ChBodyEasyCylinder` constructor:**  
  The code calls:  
  ```python
  mcrank = chrono.ChBodyEasyCylinder(chrono.ChAxis_Y, crank_rad, crank_thick, 1000)
  ```  
  According to the documentation, `ChBodyEasyCylinder` expects:  
  ```python
  ChBodyEasyCylinder(radius, height, density, visualize=True, collision=True, material=None)
  ```  
  The first argument should be the radius (float), not an axis enum. The axis is not a parameter here.  
  This is a **significant API misuse** that will cause the cylinder to be created incorrectly or raise an error.  
  Deduct **15 points** for this.

- **Incorrect use of `SetRot` with `chrono.Q_ROTATE_Y_TO_Z` and `chrono.Q_ROTATE_Y_TO_X`:**  
  These constants are not standard in the documentation. The correct way to set rotation is using `chrono.Q_ROTATE_Y_TO_Z` or `chrono.Q_ROTATE_Z_TO_X`? The code uses `chrono.Q_ROTATE_Y_TO_Z` and `chrono.Q_ROTATE_Y_TO_X` (the latter is not in the doc).  
  The documentation shows `chrono.Q_ROTATE_Z_TO_X` but not `Q_ROTATE_Y_TO_X`. This may cause errors or unexpected rotations.  
  Deduct **10 points** for incorrect or undefined rotation constants.

- **Incorrect initialization of motor joint:**  
  The motor is initialized with:  
  ```python
  my_motor.Initialize(mcrank, mfloor, chrono.ChFramed(crank_center))
  ```  
  The documentation shows that `Initialize` expects a `chrono.ChCoordsysD` (or `chrono.ChCoordsys`) for the frame, not `chrono.ChFramed`. `ChFramed` is not a documented class in the provided API.  
  This is a **significant error** that will cause the motor to not initialize properly.  
  Deduct **15 points** for this.

- **Incorrect initialization of joints:**  
  Similarly, the spherical joints and plane joint are initialized with `chrono.ChFramed(...)` instead of `chrono.ChCoordsysD(...)` or `chrono.ChCoordsys(...)`.  
  This is a **logical error** that will cause joint initialization to fail or behave incorrectly.  
  Deduct **10 points** for this.

- **Use of `my_motor.SetMotorFunction(my_angularspeed)` instead of `SetSpeedFunction`:**  
  The documentation shows the method is `SetSpeedFunction`, but the code uses `SetMotorFunction`. This is incorrect API usage.  
  Deduct **15 points** for this.

- **Use of `mpiston.GetPosDt()` instead of `mpiston.GetPos_dt()` or `mpiston.GetPos_dt()` (method name casing):**  
  The documentation does not specify `GetPosDt()`. The standard method is `GetPos_dt()` or `GetPos_dt()` (underscore). This may cause an error.  
  Deduct **5 points** for minor API misuse.

- **Closing the device inside the loop:**  
  The code calls:  
  ```python
  vis.GetDevice().closeDevice()
  ```  
  inside the loop after 20 seconds. The documentation does not mention this method, and closing the device inside the loop may cause issues. The recommended way is to break the loop or let `vis.Run()` return False.  
  Deduct **5 points** for improper visualization device handling.

**Total deductions for correctness:**  
15 (sys shadowing) + 15 (cylinder constructor) + 10 (rotation constants) + 15 (motor Initialize frame) + 10 (joint Initialize frame) + 15 (SetMotorFunction vs SetSpeedFunction) + 5 (GetPosDt) + 5 (closeDevice) = 90 points.

Since the total correctness points are 30, and deductions exceed that, cap deductions at 30.
