### 2. Correctness (30 points)

- **Body Creation API misuse:**  
  According to the documentation, `ChBodyEasySphere` and `ChBodyEasyBox` constructors have the signature:  
  ```python
  ChBodyEasySphere(radius, density, visualize=True, collision=True, material=None)  
  ChBodyEasyBox(lengthX, lengthY, lengthZ, density, visualize=True, collision=True, material=None)
  ```  
  The code calls:  
  ```python
  chrono.ChBodyEasySphere(self.system, radius, 1000, True)  
  chrono.ChBodyEasyBox(self.system, length, width, height, 1000, True)
  ```  
  Passing `self.system` as the first argument is incorrect and will cause errors. This is a **significant API misuse**. -15 points

- **CustomGravitationalForce implementation:**  
  - The class inherits from `chrono.ChForce`, but `ChForce` is an abstract base class and requires specific methods to be overridden properly.  
  - The method `ComputeF(self, time)` is defined, but the base class expects `ComputeForce` or similar (not documented here, but from experience).  
  - The force calculation applies forces by calling `ApplyForceToCOF(chrono.ChForce(...))`, which is incorrect. `ApplyForceToCOF` expects a `ChVectorD` force vector, not a `ChForce` object.  
  - The force direction is always along the Z-axis (`chrono.ChVectorD(0, 0, force)`), ignoring the actual vector between particles. This is a **logical error** in force direction.  
  - No check for zero distance (division by zero) or minimum distance threshold to avoid singularities.  
  - Forces are applied inside the force class, but forces should be computed and returned or applied properly via the system's force application mechanism.  
  - The system does not support adding custom forces this way; `AddForce()` expects a `ChForce` object properly implemented or forces applied directly to bodies each step.  
  - Overall, this is a **major logical and API misuse error**. -15 points

- **Visualization setup:**  
  - `ChVisualSystemIrrlicht` is instantiated with the system as an argument, but per documentation, it should be created empty and then attached to the system via `AttachSystem()`.  
  - Camera is set via `SetCamera()`, which is not a documented method; the documented method is `AddCamera()`.  
  - No call to `Initialize()`, `AddTypicalLights()`, or `AddSkyBox()`.  
  - The rendering loop does not check `myapplication.Run()`.  
  - These are **incorrect or missing API usages**. -15 points

- **Simulation stepping:**  
  - Uses `mysystem.DoStep()` without arguments, which is not a documented method. The correct method is `DoStepDynamics(time_step)`.  
  - No time step passed, so simulation will not advance properly. -10 points

**Deductions:**
