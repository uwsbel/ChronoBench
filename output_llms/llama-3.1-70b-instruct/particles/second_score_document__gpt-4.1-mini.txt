### 2. Correctness (30 points)

- **Collision System Setup:**  
  `sys.SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` is correct.

- **Material Usage:**  
  `ChContactMaterialNSC` is created and passed to `ChBodyEasySphere`. This is not standard usage. According to the API, `ChBodyEasySphere` expects a `ChMaterialSurface` (e.g., `ChMaterialSurfaceNSC` or `ChMaterialSurfaceSMC`), not `ChContactMaterialNSC`. The latter is a contact material, not a surface material. This is a significant API misuse and will likely cause errors or undefined behavior.

- **Particle Emitter Setup:**  
  The emitter uses `ChRandomParticlePositionOnGeometry()` with `ChBox(50,50,50)`. The `ChBox` constructor expects dimensions, but the API documentation does not specify `ChBox` as a geometry for particle positioner directly. Usually, one uses `ChBoxShape` or a mesh. This might be acceptable if `ChBox` is a valid geometry, but it's not explicitly documented. Minor uncertainty here, but likely acceptable.

- **Force Calculation:**  
  The gravitational-like force calculation is done manually between all pairs of bodies. However, the kinetic energy is summed twice per pair inside the loop over combinations, then again outside the loop for all bodies. This leads to double counting kinetic energy for each body in the pair loop and again in the separate loop. This is a logical error.

- **Force Application:**  
  Forces are accumulated correctly with `AccumulateForce`.

- **Gyro Torque:**  
  The callback disables gyro torque on bodies, which is acceptable.

- **Solver Setup:**  
  Solver type is set to PSOR with 40 max iterations, which is valid.

- **Gravity:**  
  Gravity is set to zero vector, consistent with the custom gravitational force.

- **EmptyAccumulators:**  
  Called before force accumulation, which is correct.

- **Visualization Loop:**  
  Correct usage of `vis.Run()`, `BeginScene()`, `Render()`, and `EndScene()`.

**Deductions:**

- **Incorrect use of material:** -15 points (significant API misuse).
