### 2. Correctness (30 points)

- **Particle Creation:**

  - The method `CreateParticle` creates a `chrono_particlefactory.ChParticle()` and sets mass, position, velocity, rotation, and angular velocity.  
  - However, `SetRot` and `SetRot_dt` expect unit quaternions for rotation and angular velocity. The code uses random quaternions without normalization, which can cause invalid rotations. This is a logical error.  
  - The shapes added are `chrono.ChSphereShape`, `ChBoxShape`, `ChEllipsoidShape`. According to PyChrono API, these classes do not exist or are not used for collision or visualization. The correct approach is to use `ChBodyEasySphere`, `ChBodyEasyBox`, or add collision shapes via `collision_model` or visual shapes via `AddVisualShape`. This is a significant API misuse and will cause runtime errors or no visible shapes.  
- **CustomGravity Force:**

  - The `CustomGravity` class inherits from `chrono.ChForce`, but the API documentation does not mention `ChForce` as a base class for custom forces. Usually, forces are applied via callbacks or by overriding `Update` in a different way.  
  - The `Update` method is called manually in the loop for each body, but the force is also added to the system via `system.AddForce(custom_gravity)`. This is inconsistent: either the force is managed by the system or manually updated.  
  - The force calculation uses `distance**3` in denominator and multiplies by vector `r`, which is correct for Newtonian gravity force vector.  
  - However, the force is applied only in `Update` method, which is not automatically called by the system. The system will not call `Update` on `ChForce` objects automatically. This means the gravitational force is only applied when manually called, which is done only for bodies in the loop, but the initial `custom_gravity` added to system is never updated. This is a logical error.  
- **Body Properties:**

  - `SetBodyFixed(True)` is used, but the API documentation uses `SetFixed(True)`. This is an API misuse and will cause the fixed property not to be set.  
- **Visualization:**

  - `vis.AddLogo(chrono.GetChronoDataPath() + 'logo_pychrono_alpha.png')` is used, but the API documentation recommends `chrono.GetChronoDataFile()` to get the full path. This may cause file not found errors. Minor issue.  
- **Simulation Loop:**

  - The loop calls `custom_gravity.Update(0)` for each body, but creates new `CustomGravity` instances each time, which is inefficient and unnecessary.  
  - The `system.DoStepDynamics(0.01)` is called after rendering, which is correct.

**Deductions:**  
- Incorrect shape classes for particles: **-15 points** (significant API misuse).  
- Incorrect method `SetBodyFixed` instead of `SetFixed`: **-10 points** (logical error affecting body behavior).  
- Misuse of `CustomGravity` force class and update mechanism: **-10 points** (logical error, force not applied correctly).  
- Minor issue with logo path: **-2 points**.

**Total Correctness deduction: 37 points** (cap at 30 points since total is 30)
