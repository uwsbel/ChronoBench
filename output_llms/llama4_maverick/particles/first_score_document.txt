### 2. Correctness (30 points)

- **Particle Factory Setup:**

  The line:

  ```python
  chrono_particlefactory.ChRandomParticleCreator.ParticleType(chrono_particlefactory.ChRandomParticleCreator.ParticleType_SPHERE, 
                                                              chrono_particlefactory.ChRandomParticleCreator.ParticleType_BOX, 
                                                              chrono_particlefactory.ChRandomParticleCreator.ParticleType_ELLIPSOID)
  ```

  is incorrect usage of `ParticleType`. According to PyChrono API and typical usage, `ParticleType` is an enum or integer specifying a single particle type, not a function or constructor accepting multiple types. The code attempts to pass multiple particle types at once, which is not supported. The correct approach is to create a `ChRandomShapeCreator` with a single particle type or use a different mechanism to randomize particle shapes.

  *Deduct 15 points* for incorrect API usage that would cause runtime errors or unexpected behavior.

- **CustomGravity Force:**

  - The class inherits from `chrono.ChForce`, which is a base class for forces.
  - However, `ChForce` does not have an `Update` method that is automatically called by the system.
  - The custom force is added to the system via `sys.AddForce(custom_gravity)`, but PyChrono expects forces to be subclasses of `ChForce` with proper overriding of `Update` or `UpdateForces` methods and proper registration.
  - Also, iterating over `sys.Get_bodylist()` is not the recommended way; the correct method is `sys.Get_bodylist()` (note: in PyChrono, the method is `Get_bodylist()` or `Get_bodylist()`, but the code uses `Get_bodylist()` which is acceptable).
  - The force calculation `force = -body.GetPos() * 0.1` is a vector operation, but `body.GetPos()` returns a `ChVector` and multiplying by scalar is valid.
  - However, the force is applied directly without considering mass or time step, which might be acceptable for a simple gravity-like force.
  - The main issue is that `Update` is not called automatically by the system on `ChForce` subclasses; instead, forces should override `Update` or `UpdateForces` and be registered properly.
  
  *Deduct 10 points* for logical error in force application and misunderstanding of force update mechanism.
