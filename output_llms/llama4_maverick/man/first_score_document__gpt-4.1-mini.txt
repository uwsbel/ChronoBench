### 2. Correctness (30 points)

- **Tire Initialization**:  
  The same `tire_model` instance (`veh.TMeasyTire("TMeasyTire")`) is used for multiple wheels. According to PyChrono vehicle API, each tire should be a separate instance because each tire maintains its own state. Reusing the same tire object for multiple wheels will cause incorrect behavior.  
  **Deduction: 15 points** (incorrect tire initialization).

- **Driver Synchronization and Advance Order**:  
  The driver inputs are obtained before the physics step, but `driver.Synchronize()` and `driver.Advance()` are called **after** the physics step and rendering. The recommended order is:  
  1. Synchronize driver with current time and inputs  
  2. Advance driver by step size  
  3. Advance physics system by step size  
  4. Render visualization  
  This ensures that driver inputs affect the next physics step.  
  **Deduction: 10 points** (logical error in simulation loop order).

- **Chassis Fixed Setting**:  
  `veh_sys.SetChassisFixed(False)` is called, which is fine if the chassis is intended to move. No issue here.

  The visualization system is attached to the vehicle system, but per API, it is better to attach the entire system (`vis.AttachSystem(veh_sys.GetSystem())`) to visualize all bodies, not just the vehicle. This may limit visualization of terrain or other bodies.
