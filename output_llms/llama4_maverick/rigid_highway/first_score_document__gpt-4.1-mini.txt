### 2. Correctness (30 points)

- **Order of Simulation Steps**:  
  The simulation loop calls:
  ```python
  driver_inputs = driver.GetInputs()
  vehicle.Advance(time_step)
  terrain.Advance(time_step)
  vis.Synchronize("HMMWV Simulation", driver_inputs)
  vehicle.GetSystem().DoStepDynamics(step_size)
  ```
  
  According to best practices and the API documentation, the typical order is:
  - Get driver inputs
  - Synchronize vehicle and driver with inputs and time
  - Advance driver, vehicle, terrain with the time step
  - Do system step dynamics

  Here, `vehicle.Advance()` and `terrain.Advance()` are called **before** `vis.Synchronize()`, which is incorrect because `Synchronize()` updates the vehicle and driver states with the current inputs and time. Also, `driver.GetInputs()` is called before `vis.Synchronize()`, which may cause stale inputs.

  Furthermore, `vehicle.GetSystem().DoStepDynamics(step_size)` is called **after** advancing vehicle and terrain, which is redundant and potentially incorrect because `vehicle.Advance()` internally advances the system dynamics. Calling `DoStepDynamics()` again can cause the system to advance twice per loop iteration, leading to inconsistent simulation time stepping.
