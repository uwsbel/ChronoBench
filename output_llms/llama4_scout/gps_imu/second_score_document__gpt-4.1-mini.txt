### 2. Correctness (30 points)

- **API usage:**  
  - `veh.HMMWV_Full()` is used correctly with contact method, collision type, visualization types, tire model, and step sizes.  
  - Terrain patch is created with NSC contact material and friction/restitution set properly.  
  - Visualization system is correctly initialized and attached to the vehicle.  
  - Driver inputs are set logically and synchronized properly.  
  - Sensor creation and filters are used correctly.  
  - Simulation loop calls `Synchronize()` and `Advance()` on all components in correct order.  
  - `realtime_timer.Spin(step_size)` is used to pace simulation in real time.  
  - `render_steps` and `log_steps` are calculated correctly using `math.ceil`.  
  - `gps.GetMostRecentGPSBuffer()` and `IsValid()` are used properly before accessing GPS data.  

- **Potential issues:**  
  - `offset_pose` for sensors is created using `chrono.ChFramed` and `chrono.QuatFromAngleAxis(0, chrono.ChVector3d(0, 1, 0))`. The angle is zero, so the quaternion is identity. This is acceptable but could be simplified by using `chrono.ChCoordsysD` or `chrono.ChFrameD` (depending on API version). This is a minor style issue, not correctness.  
  - The GPS sensor is given a fixed reference position `chrono.ChVector3d(-89.400, 43.070, 260.0)`, which looks like a latitude, longitude, altitude. This is acceptable but the documentation does not specify this usage explicitly. No error here.  
  - The `driver_inputs.brake` is set to 1 only after time > 6, but the initial value is never explicitly set to zero before that. However, since `driver.GetInputs()` is called each loop, this is acceptable.  
  - The vehicle's system collision type is set to `chrono.ChCollisionSystem.Type_BULLET` after vehicle initialization. This is acceptable but better practice is to set collision system type before initialization. This could cause unexpected behavior or inefficiency.  
  - `vehicle.SetChassisCollisionType(chassis_collision_type)` is set to `CollisionType_NONE`, so chassis collision is disabled. This is acceptable but may affect collision realism.  
  - The `driver` is created as `veh.ChInteractiveDriverIRR(vis)` but no explicit initialization of input devices or event handling is shown. However, `driver.Initialize()` is called, which is sufficient.  
  - The `manager.Update()` is called every loop, which is correct.  
  - The `gps_data` list is appended only if GPS buffer is valid, which is correct.  

**Deduction:**  
- 10 points for setting collision system type after vehicle initialization (could cause issues or inefficiency).  
- 5 points for minor style issue with sensor offset pose creation (could be simplified).
