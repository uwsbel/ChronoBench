### 2. Correctness (30 points)

- **Use of Vehicle API:**  
  The vehicle is initialized correctly with contact method, chassis collision type, visualization types, tire model, and step sizes.  
  **Correct.**

- **Collision System:**  
  The collision system type is set to `chrono.ChCollisionSystem.Type_BULLET` after vehicle initialization. This is correct and recommended for vehicle simulations.  
  **Correct.**

- **Driver Inputs:**  
  The `PathFollower.update()` method calculates error based on distance from a target point and applies a PID controller to steering input. However, the error calculation is `distance - radius`, where `distance` is the distance from the vehicle position to the target point. The target point is fixed at `(radius, 0, 0)`. This means the vehicle is trying to maintain a fixed distance from a fixed point, not follow a path or circle. The sentinel point is defined but unused in control logic. This is a logical error in path following: the vehicle will steer based on distance from a fixed point, which is not a proper path following behavior for a circular path.  
  **Deduct 10 points for logical error in control logic.**

- **DriverInputs:**  
  The throttle is fixed at 0.3 and braking at 0, which is acceptable for a simple demo.  
  **No deduction.**

- **Use of `vehicle.GetVehicle().GetPos()`:**  
  The `vehicle` variable is a `veh.HMMWV_Full()` object. It does not have a `GetVehicle()` method according to the API; the vehicle object itself provides `GetPos()`. This will cause an AttributeError at runtime. The correct call should be `vehicle.GetPos()`.  
  **Deduct 15 points for incorrect API usage that will cause runtime error.**

- **Use of `chrono.QUNIT`:**  
  Used correctly for identity quaternion.  
  **Correct.**

- **Use of `ChBodyEasySphere`:**  
  The sentinel and target spheres are created with default visualization and collision enabled (default parameters). This is acceptable.  
  **Correct.**

- **Use of `vis.Synchronize(time, driver_inputs)`:**  
  According to the API, `ChWheeledVehicleVisualSystemIrrlicht`'s `Synchronize` method takes `(time, driver_inputs)`. This is correct.  
  **Correct.**

- **Advancing simulation:**  
  The script advances terrain, vehicle, and visualization by `step_size` each iteration, which is correct.  
  **Correct.**

**Correctness deduction: 25 points (15 for incorrect API call `GetVehicle()`, 10 for logical error in path following control)**
