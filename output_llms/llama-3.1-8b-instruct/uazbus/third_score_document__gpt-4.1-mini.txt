### 2. Correctness (30 points)

- **Adding Obstacle to System:**  
  The line:  
  ```python
  vehicle.GetSystem().Add(vehicle.GetSystem().GetBodyList().Append(obstacle))
  ```  
  is incorrect. `GetBodyList()` returns a container, and `Append()` returns `None` (or does not return the body). The correct way is simply:  
  ```python
  vehicle.GetSystem().Add(obstacle)
  ```  
  This is a significant API misuse that will cause the obstacle not to be added properly.  
  **Deduction: 15 points**

- **Obstacle Properties:**  
  - `obstacle.SetMass(1)` is okay but very low for a fixed obstacle (usually mass is irrelevant if fixed).  
  - `obstacle.SetInertia(1,1,1)` is invalid; the API expects `SetInertiaXX(chrono.ChVector3d(...))` or `SetInertia(chrono.ChVector3d(...))`. The method `SetInertia()` with three floats is not documented.  
  - `obstacle.SetSize(0.5, 5, 0.2)` is not a valid method of `ChBody`. The size should be set via collision or visual shapes, not directly.  
  - Collision shape is added via `SetCollisionShape()`, but this method does not exist in the documented API. Instead, collision shapes are added via `collision_model` or helper functions like `AddCollisionShape()`.  
  These are multiple logical and API errors.  
  **Deduction: 15 points**

- **Collision System Type:**  
  The collision system type is set after vehicle initialization:  
  ```python
  vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)
  ```  
  This is acceptable but ideally should be set before initialization to ensure proper setup. Minor issue.  
  **Deduction: 5 points**

- **Chrono Data Path Setting:**  
  The code calls:  
  ```python
  chrono.SetChronoDataPath(chrono.GetChronoDataPath())
  ```  
  This is redundant and unnecessary, but not harmful.  
  **No deduction**

- **Tire Step Size:**  
  Tire step size is set equal to the main step size, which is acceptable.  
  **No deduction**

- **Summary Correctness Deduction:** 15 + 15 + 5 = 35 points (capped at 30 max, so 30 points deducted)
