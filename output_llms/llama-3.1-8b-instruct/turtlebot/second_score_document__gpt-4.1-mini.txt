### 2. Correctness (30 points)

- **Collision Material:** `ground_mat` is created as `ChContactMaterialNSC()` but no friction or damping is set. According to best practices, friction should be set for contact materials to avoid unrealistic behavior. This is a minor omission but can affect simulation realism. Deduct 5 points.

- **Ground Body Creation:** `ChBodyEasyBox` is used with `ground_mat` passed as the material. This is correct.

- **Robot Initialization:** `turtlebot.TurtleBot(system, init_pos, init_rot)` is called, then `robot.Initialize()`. According to the API docs, this is correct.

- **Motor Speed Settings:** The `move()` function calls `robot.SetMotorSpeed(speed, wheel_index)`. The order of arguments is `(speed, wheel_index)`. The code uses `robot.SetMotorSpeed(0, 0)` and `robot.SetMotorSpeed(0, 1)` for straight, which sets both wheels to zero speed — this means the robot will not move straight but stay still. This is a logical error.

  For moving straight, both wheels should have the same non-zero speed (e.g., `robot.SetMotorSpeed(math.pi, 0)` and `robot.SetMotorSpeed(math.pi, 1)`).

  Similarly, for turning left, the left wheel should have a negative speed and the right wheel positive or zero, but the code sets left wheel to `-math.pi` and right wheel to `0`, which will cause a pivot turn rather than a smooth left turn. This might be acceptable depending on the robot's kinematics, but the straight movement is definitely incorrect.

  Deduct 10 points for logical error in motor speed settings.

- **Visualization Camera:** `vis.AddCamera(chrono.ChVector3d(0, 1.5, 0.2), chrono.ChVector3d(0, 0, 0.2))` is used. The API docs show `AddCamera(position)` with one argument, but here two arguments are passed. According to PyChrono API, `AddCamera()` takes only one argument (position). The second argument is not documented and likely incorrect.

  Deduct 15 points for incorrect API usage in `AddCamera()`.
