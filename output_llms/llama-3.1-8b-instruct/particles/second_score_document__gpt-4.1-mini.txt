### 2. Correctness (30 points)

- **Use of `ChContactMaterialNSC` in `ChBodyEasySphere`:** The constructor expects a material pointer or None. The code passes `sphere_mat` which is a `ChContactMaterialNSC` instance. According to PyChrono API, `ChBodyEasySphere` expects a `ChMaterialSurface` or None, not a `ChContactMaterialNSC` directly. The correct approach is to create a `ChMaterialSurfaceNSC` and assign friction etc. The code uses `ChContactMaterialNSC` incorrectly here.

- **`SetUseGyroTorque(False)`:** This disables gyroscopic torque on bodies, which is acceptable but unusual for spheres. No error but might affect realism.

- **Energy calculation:** The kinetic energy is computed using acceleration squared times mass, which is physically incorrect. Kinetic energy should be computed using velocity squared:  
  \[
  KE = \frac{1}{2} m v^2
  \]  
  The code uses acceleration (`GetAcceleration()`) instead of velocity (`GetPos_dt()` or `GetPos_dtdt()`), which is a logical error.

- **Force accumulation:** The gravitational-like force is applied pairwise correctly, but the gravitational constant is set to `6.674e-3`, which is arbitrary and not physically meaningful. This is acceptable for simulation but should be noted.

- **Calling `body.EmptyAccumulators()` before force accumulation:** This is correct.

- **`emitter.EmitParticles(sys, stepsize)`:** Correct usage.

- **`sys.DoStepDynamics(stepsize)`:** Correct usage.

**Deductions:**

- 15 points for incorrect use of `ChContactMaterialNSC` in `ChBodyEasySphere` (significant API misuse).

- 10 points for logical error in kinetic energy calculation (using acceleration instead of velocity).
