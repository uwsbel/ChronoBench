### 2. Correctness (30 points)

- **Use of `SetAutomaticGravity(True, 2)` on mesh:**  
  According to best practices, gravity is usually set on the system (`sys.SetGravitationalAcceleration(...)`). Setting gravity on the mesh with `SetAutomaticGravity(True, 2)` is allowed but the second argument `2` is undocumented in the provided docs and unclear. This might be a minor misuse or at least unclear usage.  
  **Minor inaccuracy:** -5 points.

- **Use of `chrono.ChLinkMateGeneric(False, True, True, False, True, True)` for bearing:**  
  The parameters correspond to enabling/disabling constraints on translation and rotation axes. This is acceptable but the frame used for initialization is `chrono.ChFramed(...)` which is not a documented class in the provided docs (the docs mention `chrono.ChCoordsysD` or `chrono.ChCoordsysd`). This could cause an error or unexpected behavior.  
  **Incorrect API usage:** -15 points.

- **Use of `rotmotor1.SetMotorFunction(custom_fun)` instead of `SetSpeedFunction`:**  
  The documentation specifies `SetSpeedFunction(func)` for `ChLinkMotorRotationSpeed`. The code uses `SetMotorFunction`, which is not in the docs and likely incorrect.  
  **Incorrect API usage:** -15 points.

- **Use of `chrono.ChCoordsysd` vs `chrono.ChCoordsysD`:**  
  The docs use `chrono.ChCoordsysD` (capital D) for coordinate systems, but the code uses `chrono.ChCoordsysd` (lowercase d). This is a minor inconsistency but could cause runtime errors depending on the API.  
  **Minor inaccuracy:** -5 points.

- **Use of `chrono.QuatFromAngleAxis(CH_PI / 2.0, chrono.VECT_Z)` and similar:**  
  This is correct usage.

- **Use of `builder.GetLastBeamNodes().size()` in Python:**  
  `size()` is a C++ method; in Python, the length of a list is obtained by `len()`. This will cause an error.  
  **Incorrect API usage:** -15 points.

- **Use of `sys.DoStaticLinear()` before the simulation loop:**  
  This is acceptable to compute static equilibrium before dynamics. No deduction.
