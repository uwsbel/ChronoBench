### 2. Correctness (30 points)

- **Element Node Assignment:**

  The `fea.ChElementShellBST()` requires the correct ordering of nodes and boundary nodes. The code uses complex indexing with boundary nodes that sometimes may be `None`. The logic for boundary nodes is inconsistent and likely incorrect:

  - For `melementA`, boundary nodes are assigned conditionally, but the conditions are off. For example, `boundary_1` is assigned only if `ix < nsections_x`, but the loop runs `ix` in `range(nsections_x)`, so `ix` is always less than `nsections_x`. This is redundant but not harmful.

  - More importantly, the boundary nodes for `melementB` are assigned without proper boundary checks, and the nodes passed to `SetNodes` are in an unusual order. The documentation and typical usage require nodes to be passed in a specific order (three main nodes plus three boundary nodes), but the code swaps nodes in `melementB.SetNodes(...)` in a way that is likely incorrect.

  This can cause incorrect element connectivity and thus wrong simulation behavior.

- **Material Poisson Ratio:** Set to zero (`nu = 0.0`). While not incorrect, it is unusual and may cause unrealistic material behavior. Not a correctness error per se.

- **Load Application:** There is a defined `load_force` vector, but it is never applied to any node or element. This is a logical omission: the simulation applies no external forces, so the shell will not deform or respond dynamically.

- **Node Fixing:** The code fixes nodes at `j in range(nsections_z)` and `k in range(nsections_x + 1)`, i.e., all nodes except the last row (`iz == nsections_z`) are fixed. This is a valid boundary condition but should be explicitly commented for clarity.
