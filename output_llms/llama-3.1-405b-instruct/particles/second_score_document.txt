### 4. Efficiency (10 points)

- **Inefficiencies:**  
  - The gravitational force calculation uses `combinations(sys.GetBodies(), 2)` every step, which is O(n²) in the number of bodies. For large numbers of particles, this is inefficient.  
  - The code calls `sys.GetBodies()` multiple times in the loop; storing the list once per step would be more efficient.  
  - The `body.EmptyAccumulators()` is called for every body each step, which is necessary but could be done once per step outside the loop if API allows.  
  - The particle reservoir is set to 200 particles but emits 2000 particles per second, which may cause frequent reservoir depletion and reallocation overhead.  
  - The callback binds visual and collision items for every new particle, which is necessary but could be costly if many particles are created per step.  

- **Missed Optimizations:**  
  - Caching `sys.GetBodies()` in a local variable before loops to avoid repeated calls.  
  - Using spatial partitioning or approximate methods for gravitational forces to reduce O(n²) complexity (e.g., Barnes-Hut), but this is beyond the scope of this example.  
  - Potentially limiting the number of particles or optimizing particle creation parameters.  

**Deduction:**  
- One instance of inefficient O(n²) force calculation: -5 points.  
- Minor missed optimization (caching bodies list): -3 points.
