### 2. Correctness (30 points)

- **API Usage:**  
  - `veh.HMMWV_Full()` is used correctly with appropriate settings.  
  - Contact method is set before initialization, which is correct.  
  - Visualization types are set after initialization, which is acceptable but usually visualization types are set before `Initialize()`. This might cause some visualization settings to not take effect properly.  
  - `vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` is called after initialization; changing collision system type after initialization is generally not recommended and may have no effect or cause issues. This is a correctness issue.  
  - The PID controller uses the error as the distance between the vehicle and the closest path point, but steering is a signed quantity (left/right), so using only the magnitude of the error (distance) without direction will not produce meaningful steering commands. This is a logical error in control.  
  - The `vehicle_inputs` object is created every loop iteration, which is fine but could be optimized.  
  - The `vis.AddSphere()` method is used to add spheres for path visualization, but according to the API, `AddSphere()` returns a visual shape pointer, but the code stores them in a list without further use. This is not an error but the spheres are static and do not update, which is acceptable.  
  - The simulation advances vehicle, terrain, and visualization separately, which is correct.  
  - The realtime timer usage is correct.  
  **Deduct 15 points for the incorrect steering control logic (sign/direction missing).**  
  **Deduct 10 points for changing collision system type after initialization (incorrect API usage).**
