### 2. Correctness (30 points)

  All API calls conform to the documented usage. The vehicle is initialized correctly, visualization is set properly, terrain material is set with friction and restitution, and the contact system type is set to BULLET as recommended for NSC systems.

- **Logical correctness:**  
  The lane change steering logic is a bit unusual but not incorrect: it linearly ramps steering from -1 to +1 scaled to ±0.5 max steering. The throttle is set to 0 after the maneuver. This is logically sound.

- **Driver inputs:**  
  The driver inputs are fetched and then overwritten with the lane change logic values. This is acceptable since the interactive driver is used but overridden by the script logic.

- **Collision system:**  
  The collision system type is set after vehicle initialization. This is acceptable but ideally should be set before initialization to ensure proper setup. However, the vehicle's `Initialize()` is called before setting collision system type on `vehicle.GetSystem()`. This could cause issues if the collision system type is not set early enough.  
  **Deduct 10 points** for this important detail that could affect collision behavior.

- **Step sizes:**  
  Step sizes are consistent and small enough for stable simulation.

- **Use of `chrono.SetChronoDataPath(chrono.GetChronoDataPath())`:**  
  This line is redundant (setting the data path to itself). It is harmless but unnecessary.  
  **Deduct 5 points** for minor unnecessary API call.
