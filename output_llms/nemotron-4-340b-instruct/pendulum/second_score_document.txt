### 2. Correctness (30 points)

- **API Usage:**
  - `sys.SetGravitationalAcceleration(chrono.ChVector3d(0, -1.62, 0))` is correct.
  - Ground body created with `chrono.ChBody()`, added with `sys.Add(ground)`. This is correct, but the recommended method is `sys.AddBody(body)` for bodies. The code uses `sys.Add(ground)` for ground and `sys.AddBody(pend_1)` for pendulum. This inconsistency is minor but could cause confusion.
  - According to the API, `sys.AddBody()` is the preferred method to add bodies. `sys.Add()` is a generic method that can add bodies, links, etc., but `AddBody()` is clearer and preferred.
  - **Deduct 5 points** for inconsistent use of `sys.Add()` vs `sys.AddBody()`.
- **Joint Initialization:**
  - The spherical joint is initialized with `chrono.ChFramed(...)`. The API documentation specifies `chrono.ChCoordsysD` or `chrono.ChCoordsys` for joint frames.
  - `chrono.ChFramed` is not a standard PyChrono class or alias in the documentation; the correct class is `chrono.ChCoordsysD` or `chrono.ChCoordsys`.
  - Using `chrono.ChFramed` is incorrect and will cause an error.
  - **Deduct 15 points** for incorrect joint initialization frame.
- **Visual Shape Initialization:**
  - The pendulum visual shape is added with a frame using `chrono.ChFramed(chrono.VNULL, chrono.QuatFromAngleY(chrono.CH_PI_2))`.
  - Again, `chrono.ChFramed` is not a documented class; the correct class is `chrono.ChCoordsysD` or `chrono.ChCoordsys`.
  - **Deduct 15 points** for incorrect use of `chrono.ChFramed` in visual shape frame.
- **Angular Velocity Setting:**
  - `pend_1.SetWvel(chrono.ChVector3d(0, 0, 1))` is correct.
- **Logging:**
  - Uses `pend_1.GetPos()` and `pend_1.GetPosDt()` which are correct.
- **Overall correctness deductions:**
