### 2. Correctness (30 points)

- **Quaternion Initialization:**  
  The initial rotation quaternion is set as `chrono.ChQuaterniond(math.sqrt(0.5), 0, 0, math.sqrt(0.5))` to represent a 45° rotation around Z axis.  
  The quaternion for rotation about Z by angle θ is (cos(θ/2), 0, 0, sin(θ/2)). For 45°, cos(22.5°) ≈ 0.924, sin(22.5°) ≈ 0.383. Using sqrt(0.5) ≈ 0.707 is incorrect here. This quaternion corresponds to a 90° rotation around Z or 45° around X or Y depending on order, but not 45° around Z.  
  **Deduct 10 points** for incorrect quaternion initialization.

- **Vehicle Visualization Type Setting:**  
  The calls to `SetChassisVisualizationType(vis_type, vis_type)` and similar for steering, suspension, wheels, and tires use two arguments, but the API typically expects a single argument for visualization type. The double argument usage is inconsistent with the API documentation.  
  **Deduct 5 points** for incorrect or unnecessary API calls.

- **Vehicle Collision Type:**  
  `chassis_collision_type` is set to `veh.CollisionType_NONE`, which disables chassis collision. This is acceptable if intended, but generally chassis collision is enabled for realistic simulations. No error here, but could be a design choice.  
  **No deduction.**

- **Vehicle System Collision Type:**  
  The system collision type is set to `chrono.ChCollisionSystem.Type_BULLET` after vehicle initialization. This is acceptable but usually set before initialization to ensure proper collision system creation. Setting it after initialization may have no effect or cause issues.  
  **Deduct 5 points** for potential logical error in collision system setting order.

- **Driver Inputs Modification:**  
  The lane change modifies `driver_inputs.m_steering` directly. The `driver_inputs` object is obtained via `driver.GetInputs()`. Modifying the returned inputs may not affect the driver module's internal state unless explicitly set back or the driver is designed to accept external input modifications this way. This is a logical error.  
  **Deduct 10 points** for logical error in driver input handling.

- **Vehicle Attachment to Visualization:**  
  As noted above, `vis.AttachVehicle(vehicle.GetTractor())` is suspicious. The `Kraz` vehicle class does not have a documented `GetTractor()` method. This likely causes runtime errors or no visualization.  
  **Already deducted 10 points above for this.**

- **Summary:**  
  Major issues with quaternion, driver input modification, and visualization attachment. Minor issue with visualization type calls and collision system setting order.  
  Total deduction: 10 + 10 + 5 + 5 = 30 points.
