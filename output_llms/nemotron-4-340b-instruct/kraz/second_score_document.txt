### 2. Correctness (30 points)

- **Quaternion Initialization:**  
  The initial rotation quaternion is set as `chrono.ChQuaterniond(math.sqrt(0.5), 0, 0, math.sqrt(0.5))` intending a 45° rotation around Z axis.  
  The quaternion for rotation by angle θ around Z is:  
  q = [cos(θ/2), 0, 0, sin(θ/2)]  
  For 45°, θ/2 = 22.5°, cos(22.5°) ≈ 0.924, sin(22.5°) ≈ 0.383.  
  The code uses sqrt(0.5) ≈ 0.707 for both w and z components, which corresponds to a 90° rotation, not 45°.  
  This is a **minor inaccuracy**.  
  **Deduct 5 points.**

- **Vehicle Visualization Type Setting:**  
  The code calls `vehicle.SetChassisVisualizationType(vis_type, vis_type)` and similarly for steering, suspension, wheels, tires, passing two arguments each time. According to the API, these methods take a single argument specifying visualization type. Passing two arguments is incorrect and will cause an error or unexpected behavior.  
  This is a **significant API misuse**.  
  **Deduct 15 points.**

- **Collision System Type:**  
  The code sets the collision system type to `chrono.ChCollisionSystem.Type_BULLET` on `vehicle.GetSystem()`. This is correct and recommended for complex vehicle simulations.  
  **No deduction.**

- **Terrain Material:**  
  The terrain patch material is created with friction and restitution set, which is correct.  
  **No deduction.**

- **Visualization Attach Vehicle:**  
  As noted above, `vis.AttachVehicle(vehicle.GetTractor())` is incorrect; `GetTractor()` is not a method of `veh.Kraz`. The correct call is `vis.AttachVehicle(vehicle)`.  
  **Deduct 15 points** (already counted under completeness, but correctness is the root cause).

- **Driver Input Modification:**  
  Modifying `driver_inputs.m_steering` directly will not affect the driver’s internal state or vehicle control. The driver interface does not support external input injection this way. The proper way is to subclass the driver or use a custom driver.  
  **Deduct 10 points** (already counted under completeness).

- **Use of `vehicle.GetSteering().GetMaxSteeringAngle()`:**  
  This is correct to normalize steering input.  
  **No deduction.**
