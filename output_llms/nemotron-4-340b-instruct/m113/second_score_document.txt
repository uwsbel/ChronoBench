  This is a **significant correctness error** and will cause the script to fail immediately.  
  **Deduct 15 points.**

- **Setting `chassis_collision_type` but not applying it**:  
  The variable `chassis_collision_type` is set to `veh.CollisionType_NONE` but never used in the vehicle setup. According to the API, the chassis collision type should be set via `vehicle.SetChassisCollisionType(chassis_collision_type)`. This is missing.  
  This omission affects collision behavior and is an important detail.  
  **Deduct 10 points.**

- **Setting contact system type after vehicle initialization**:  
  The code calls `vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` after vehicle initialization. According to best practices, the collision system type should be set **before** vehicle initialization to ensure proper setup.  
  This could lead to inconsistent collision behavior.  
  **Deduct 10 points.**

- **Hardcoding throttle input after synchronization**:  
  The throttle input is hardcoded to 0.8 **after** the driver synchronization step. This means the driver’s internal state is updated with old inputs, and then the throttle is overridden, which is logically inconsistent.
