### 2. Correctness (30 points)

- **Incorrect use of `ChBodyEasy*` constructors:**  
  According to the documentation, `ChBodyEasySphere` and others require parameters: `(radius, density, visualize, collision, material)`. The code calls, e.g.,  
  ```python
  chrono.ChBodyEasySphere(self.sys, 1, 1000, contact_material)
  ```  
  which is incorrect. The first argument should be the radius (float), not the system, and the `visualize` and `collision` booleans are missing. This will cause runtime errors or incorrect behavior.  
  Deduct **15 points** for significant API misuse.

- **Rotation setting:**  
  The code uses `chrono.Q_from_AngXAxis(np.random.uniform(0, np.pi))` which is not a documented PyChrono function. The correct function is `chrono.Q_from_AngAxis(angle, axis)` or `chrono.Q_from_AngAxis(angle, chrono.ChVectorD(x,y,z))`. This will cause an AttributeError or incorrect rotation.  
  Deduct **15 points** for incorrect API usage.

- **CustomGravitationalForce:**  
  The class inherits from `chrono.ChForce`, but the method `ComputeF(self, x, v, m)` is not a documented override in PyChrono. PyChrono forces typically override `Update` or `UpdateForces` methods and use `AddForce` with a `ChForce` subclass properly initialized. Also, the force calculation does not consider zero-distance or very small distances, which can cause division by zero or numerical instability.  
  Deduct **10 points** for logical errors and incorrect force implementation.

- **Force application:**  
  The force is created once per particle and added, but no mechanism to update the force each timestep is present. This means the force will not be updated dynamically during simulation.  
  Deduct **10 points** for logical error in force application.

- **Visualization loop:**  
  The code uses `vis.DrawAll()` instead of the documented `vis.Render()`. This is a minor API misuse.
