### 2. Correctness (30 points)

- **PID Controller Implementation:**  
  The derivative term calculation is incorrect. The code uses:  
  ```python
  pid_derivative = (pid_error - pid_derivative) / step_size
  ```  
  Here, `pid_derivative` is used on the right side as the previous error, but it actually holds the previous derivative value, not the previous error. This will cause incorrect derivative calculation and likely unstable control. The standard PID derivative term is:  
  ```python
  derivative = (current_error - previous_error) / dt
  ```  
  But the code uses `pid_derivative` instead of storing previous error separately. This is a logical error.  
  **Deduct 10 points for logical error in PID derivative calculation.**

- **PID Output Usage:**  
  The computed `throttle_input` is never clamped or limited to [0,1] or any valid input range. Also, it is never applied to the driver or vehicle throttle input. This is a correctness issue affecting simulation behavior.  
  **Deduct 15 points for incorrect use of PID output (not applied).**

- **Vehicle Initialization:**  
  The vehicle is initialized before setting visualization types. According to best practices, visualization types should be set before `Initialize()`. The code calls `Initialize()` first, then sets visualization types. This may cause visualization settings to be ignored or not applied properly.  
  **Deduct 10 points for incorrect order of visualization setup.**

- **Use of `vehicle.GetVehicle().GetSpeed()` for speed:**  
  This is correct usage to get vehicle speed in m/s. However, `reference_speed` is in km/h, so the error calculation mixes units:  
  ```python
  speed_error = reference_speed - vehicle.GetVehicle().GetSpeed()
  ```  

  This subtracts m/s from km/h, which is incorrect. Units must be consistent.  
  **Deduct 10 points for unit inconsistency in speed error calculation.**
