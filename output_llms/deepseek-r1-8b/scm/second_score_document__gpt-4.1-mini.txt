### 2. Correctness (30 points)

- **Terrain Parameters Misassignment**:  
  The call to `terrain_params.SetParameters()` uses `terrainHeight` (which is 0) as `Bekker_Kphi`. This is incorrect because `Bekker_Kphi` is a soil parameter related to pressure-sinkage modulus, not terrain height. The terrain height should not be passed as a soil parameter.  
  This will significantly affect simulation behavior.  
  **Deduct 15 points**.

- **Accessing Terrain Parameters via Properties**:  
  The `SCM_Terrain_Params` class defines some properties like `GetBekker_Kphi`, but only two properties are defined (`GetBekker_Kphi` and `GetBekker_Kc`). The rest of the parameters are accessed directly (e.g., `terrain_params.GetMohr_cohesive_limit`), but these are not defined as properties or attributes. This will cause an `AttributeError`.  
  This is a significant error.  
  **Deduct 15 points**.

- **Collision System Type Setting**:  
  The code calls `vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)`. According to the documentation, the collision system type should be set on the system before adding bodies or initializing the vehicle. Setting it after vehicle initialization may not have the intended effect.  
  This is a logical error that could affect collision detection.  
  **Deduct 10 points**.

- **Use of `veh.SetDataPath`**:  
  The code calls `veh.SetDataPath(chrono.GetChronoDataPath() + 'vehicle/')`. This is correct but assumes the trailing slash is correct for the OS. Minor issue but no deduction.

- **Use of `driver.GetInputs()` before `driver.Synchronize()`**:  
  The code calls `driver.GetInputs()` before calling `driver.Synchronize(time)`. According to best practices, synchronization should happen before getting inputs to ensure inputs are updated for the current time step. This is a minor logical error.  
  **Deduct 5 points**.

- **Use of `vehicle.GetVehicle().GetMass()`**:  
  The code prints vehicle mass by calling `vehicle.GetVehicle().GetMass()`. This is correct usage.
