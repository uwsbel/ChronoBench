### 2. Correctness (30 points)

- **System and collision setup:** Correct.

- **Ground body:** Uses `ChContactMaterialNSC()` but does not set friction or damping properties. While not strictly required, best practice is to set friction to a reasonable value to avoid unrealistic sliding.  
  **Deduct 5 points** minor inaccuracy / missing important detail.

- **Boxes:** Created with random positions in a large cube from -10 to 10 in all axes, including z from -10 to 10. This means some boxes will be below the ground (ground at z=-0.6, boxes can be at z=-10). This is likely unintended and could cause boxes to start embedded underground.  
  **Deduct 10 points** for logical error in initial placement of boxes.

- **Robot motor control:**  
  - `move()` function calls `robot.SetMotorSpeed(0, LEFT_DRIVE_WHEEL)` etc.  
  - The order of arguments is `(speed, wheel_index)` which matches the example usage.  
  - However, the constants `LEFT_DRIVE_WHEEL` and `RIGHT_DRIVE_WHEEL` are defined inside the loop after the first call to `move()`. This will cause a `NameError` on first call to `move('left')` at time=1.0.  
  - This is a significant correctness issue.  
  **Deduct 15 points** for incorrect use of variables leading to runtime error.

- **Sensor usage:**  
  - `sens` is imported as `from pychrono.sensor import *`, but sensor manager is created as `sens.ChSensorManagerNSC()`.  
  - The code uses `sens.ChLidarSensorNSC()`. This is correct usage.  
  - However, the sensor is added to the system via `system.Add(lidar_sensor)`. According to PyChrono API, sensors are managed by the sensor manager, which should be added to the system, but individual sensors are typically attached to the sensor manager, not directly added to the system.  
  - The correct usage is to add the sensor to the sensor manager, e.g., `sensor_manager.AddSensor(lidar_sensor)`.  
  - Adding the sensor directly to the system is incorrect and may cause the sensor not to function properly.  
  **Deduct 15 points** for incorrect API usage of sensor addition.

- **Visualization:**  
  - `vis.AddCamera()` is called with two arguments: position and look-at vector. The API documentation shows `AddCamera(position)` only.  
  - The code uses `vis.AddCamera(chrono.ChVector3d(0, 1.5, 0.2), chrono.ChVector3d(0, 0, 0.2))`.  
  - According to the API, `AddCamera()` takes only one argument (position).  
  - This is an incorrect API usage and may cause an error or unexpected behavior.  
  **Deduct 15 points** for incorrect visualization API usage.

- **Motor speed setting:**  
  - The `move()` function sets motor speeds to 0 or ±π rad/s. This is acceptable, but the initial call `move('straight')` sets both speeds to 0, which means the robot is stationary initially. This is not an error, but could be clarified. No deduction.
