### 2. Correctness (30 points)

- **API Usage:**  
  - `veh.HMMWV_Full()` is correctly used with contact method, collision type, and initialization.  
  - Terrain patch is created with `ChContactMaterialNSC()` and friction/restitution set properly.  
  - Visualization system is correctly set up and attached.  
  - Driver deltas are set based on render step size and times, which is correct.  
  - Sensors are created with correct parameters and filters pushed.  
  - The simulation loop correctly synchronizes and advances all components.  
  - `realtime_timer.Spin(step_size)` is used properly for real-time pacing.  
  - GPS data extraction uses `GetMostRecentGPSBuffer().GetGPSData()` correctly.  
  - The plotting uses latitude and longitude axes correctly.  

- **Potential issues:**  
  - `vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` is called **after** vehicle initialization. According to best practices, collision system type should be set **before** initializing the vehicle to ensure proper collision system creation. Setting it afterward may have no effect or cause unexpected behavior.  
  - The `offset_pose` for sensors is created with `chrono.ChFramed` instead of `chrono.ChFrameMoving` or `chrono.ChCoordsysd`. The documentation and examples typically use `chrono.ChFrameMoving` or `chrono.ChCoordsysd` for sensor offset poses. `ChFramed` is a lower-level class and may not be appropriate here. This could cause subtle issues in sensor pose handling.  
  - The GPS sensor is initialized with a fixed reference coordinate `chrono.ChVector3d(-89.400, 43.070, 260.0)`, which is unusual because GPS reference coordinates should be latitude, longitude, altitude. The values seem to be longitude, latitude, altitude but swapped. Latitude is usually first. This might cause incorrect GPS data interpretation.  
  - The driver inputs are set to fixed throttle and steering values every loop iteration without any logic or user input, which is acceptable for a demo but not realistic.  
  - The `vehicle.GetVehicle().GetMass()` call is correct but `vehicle.GetVehicle()` is a bit redundant since `vehicle` is already a vehicle object. Minor inefficiency but no correctness issue.  

**Deductions:**  
- Collision system type set after initialization: **-15 points** (significant potential impact)  
- Use of `chrono.ChFramed` for sensor offset pose instead of recommended `ChFrameMoving` or `ChCoordsysd`: **-10 points** (incorrect or suboptimal API usage)  
- GPS reference coordinates possibly swapped (longitude and latitude order): **-10 points** (logical error affecting GPS data correctness)  

**Correctness score:** 30 - 15 - 10 - 10 = **-5**, but minimum is 0, so **0**
