### 2. Correctness (30 points)

- **API usage correctness:**  
  - `ChBodyEasyCylinder` usage: The first argument is an axis enum (`chrono.ChAxis_Y`), which is correct per documentation.  
  - Positions and rotations of bodies are set with `SetPos` and `SetRot` using `chrono.Q_ROTATE_Y_TO_Z` and `chrono.Q_ROTATE_Y_TO_X`. These are predefined quaternions in PyChrono and used correctly.  
  - Motor initialization uses `chrono.ChFramed(crank_center)`. However, the documentation and examples use `chrono.ChCoordsysD` (or `chrono.ChCoordsys`) for frames, not `ChFramed`. `ChFramed` is not a standard PyChrono class or constructor. This is a significant API misuse that will cause runtime errors. The correct call should be something like:  
    ```python
    chrono.ChCoordsysD(crank_center)
    ```  
    or  
    ```python
    chrono.ChCoordsys(crank_center)
    ```  
  - Similarly, revolute and prismatic joints are initialized with `chrono.ChFramed(...)`, which is incorrect. The API requires `chrono.ChCoordsysD` or `chrono.ChCoordsys`.  
  - Accessing rotation angles:  
    - `mcrank.GetRot().yAngle()` and `mcrank.GetDerivRot().yAngle()` are used. The `GetRot()` returns a quaternion, but `yAngle()` is not a documented method of quaternion in PyChrono. The correct way to get Euler angles is to convert the quaternion to Euler angles explicitly or use `GetRot().Q_to_Euler123()` or similar.  
    - `GetDerivRot()` returns the quaternion derivative, not angular velocity. Angular velocity should be obtained via `GetWvel_loc()` or `GetWvel_par()` or `GetWvel()`.  
    - Using `yAngle()` on quaternion or its derivative is incorrect and will cause errors or wrong results.  
  - Position data collected is `mcrank_pos.y`, but the piston moves along the X-axis, so piston position should be from `mpiston.GetPos().x` or similar, not crank's Y position.  
  - Plotting piston speed uses `mcrank_speed`, which is incorrectly obtained and also from the crank, not the piston.  
  - Motor speed function is created with `chrono.ChFunctionConst(chrono.CH_PI)`, but the method called is `SetMotorFunction()`. The API uses `SetSpeedFunction()`. This is a naming mismatch and will cause an error.  
  - The simulation loop uses `time = sys.GetChTime()`, which is correct.  
  - The time step of 1e-3 is reasonable.  
  - The visualization loop is correctly structured.

**Summary of correctness issues:**  
- Use of `chrono.ChFramed` instead of `chrono.ChCoordsysD` or `chrono.ChCoordsys` for joint and motor initialization. **(-15 points)**  
- Incorrect methods to extract angles and angular velocities from quaternions (`yAngle()` on quaternion and derivative). **(-15 points)**  
- Use of `SetMotorFunction()` instead of `SetSpeedFunction()` for motor speed function. **(-15 points)**  
- Logical error: collecting piston position and speed from crank body instead of piston body. **(-10 points)**

Since the total correctness deduction is capped at 30 points, we assign the maximum deduction here.

**Correctness deduction: 30 points**
