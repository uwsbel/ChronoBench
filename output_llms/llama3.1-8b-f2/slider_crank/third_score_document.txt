### 2. Correctness (30 points)

- **Body Creation:**  
  The use of `ChBodyEasyCylinder(chrono.ChAxis_Y, radius, thickness, density)` is incorrect because the PyChrono API for `ChBodyEasyCylinder` expects parameters as `(radius, height, density, visualize=True, collision=True, material=None)`. The first argument should be radius (float), not an axis enum.  
  The code uses `chrono.ChBodyEasyCylinder(chrono.ChAxis_Y, crank_rad, crank_thick, 1000)` which is wrong.  
  This will cause an error or unexpected behavior.  
  **Deduct 15 points** for incorrect API usage.

- **Rotation of crank:**  
  The code uses `mcrank.SetRot(chrono.Q_ROTATE_Y_TO_Z)` which is a valid predefined quaternion for rotating Y-axis aligned cylinder to Z-axis.  
  **No deduction.**

- **Motor joint initialization:**  
  The motor is initialized with `chrono.ChFramed(crank_center)`. The API documentation shows `chrono.ChCoordsysD(position, rotation)` is expected. `ChFramed` is a C++ class; in Python, `ChCoordsysD` or `ChCoordsys` is used.  
  This is a mismatch and likely incorrect.  
  **Deduct 15 points** for incorrect joint initialization frame type.

- **Motor speed function:**  
  Uses `chrono.ChFunctionConst(chrono.CH_PI)`, which is correct.  
  **No deduction.**

- **Joint initialization frames:**  
  For spherical joints and planar joint, `chrono.ChFramed` is used instead of `chrono.ChCoordsysD` or `chrono.ChCoordsys`. This is inconsistent with the API and likely incorrect.  
  **Deduct 10 points** for logical errors in joint initialization.

- **Stopping condition:**  
  The simulation stops after 20 seconds by calling `vis.GetDevice().closeDevice()`. This is an acceptable way to stop the Irrlicht window.  
  **No deduction.**

- **Data collection:**  
  Uses `my_motor.GetMotorAngle()`, `mpiston.GetPos().x`, and `mpiston.GetPosDt().x` which are correct calls.  
  **No deduction.**
