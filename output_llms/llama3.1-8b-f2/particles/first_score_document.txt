### 2. Correctness (30 points)

- **Incorrect use of PyChrono API:**  
  - The use of `TopoDS.TopoDS_Shape()` directly is invalid; it is an abstract class and cannot be instantiated.  
  - Setting mass, position, rotation on a shape object (`cube`) instead of a `ChBody` is incorrect.  
  - The collision shape creation is unusual: `chrono.ChCollisionShapeBullet(cube, mcoll)` is not a documented constructor in the PyChrono API. Usually, collision shapes are added via `body.GetCollisionModel().AddBox()` or similar, or by using `ChBodyEasyBox` or `ChBodyEasySphere`.  
  - The `body` is created but mass is never set on it; mass is set on `cube` (the shape), which is not a body. This will cause the body to have zero mass and possibly behave incorrectly.  
  - The emitter creates particles with a lifespan of `1.0 / max_particles_per_second` (which is 0.001 s), but the system lifespan is set to 0.5 s. This mismatch may cause particles to disappear almost immediately.  
  - The particle position is set repeatedly to a fixed vector `(0.1, 0.1, 0.1)` rather than relative to the emitter pose or randomized, which is not physically meaningful.  
  - The `change_particle_properties` callback sets the particle position to a fixed offset `(0.1, 0.1, 0.1)` relative to the emitter pose every frame, which will override any physics-based movement.  
  - The simulation loop calls `vis.Run()` twice per iteration: once in the `while` condition and again immediately inside the loop, which is redundant and could cause issues.  
  - The `sys.SetSolverType()` and `sys.GetSolver().AsIterative().SetMaxIterations()` are called twice: once before the loop and again inside the loop, which is unnecessary.  
  - The `sys.CheckForNullBodyPointers()` is called every loop, which is not a standard or documented method in PyChrono and may not exist. This could cause runtime errors.

  - The `particle.SetDragType(cascade.ChCascadeParticle.DRAG_TYPE_NONE)` is called, but drag is also set on the system to none; this is redundant but not harmful.  

**Major API misuse and logical errors:**

- Instantiating `TopoDS.TopoDS_Shape()` directly (15 points)

- Redundant calls and misuse of `vis.Run()` and solver settings (5 points)
