### 2. Correctness (30 points)

- **Incorrect use of PyChrono API:**

  - **Lidar sensor creation:**  
    The constructor call:  
    ```python
    lidar_sensor = sens.ChLidarSensor(robot, 0.5, 100, 0.02, 0.02, 1, 10, 10, 1, 0, 10, 0.1, 0.1, 0.1, 0.1)
    ```  
    This is suspicious because the PyChrono API documentation does not provide a constructor with so many positional parameters for `ChLidarSensor`. Usually, sensors are created with a sensor pose and parameters passed as keyword arguments or via setters. Without the exact API signature, this looks like a misuse or at least unclear usage.  
    **Deduct 15 points** for incorrect API usage that could affect sensor behavior.

  - **Setting filters on lidar sensor:**  
    ```python
    lidar_sensor.SetFilter(sens.ChFilterAccess::FILTER_NONE)
    lidar_sensor.SetFilter(sens.ChFilterAccess::FILTER_LINEAR_KALMAN)
    lidar_sensor.SetFilter(sens.ChFilterAccess::FILTER_NEAREST_NEIGHBOR)
    ```  
    - The syntax `sens.ChFilterAccess::FILTER_NONE` is invalid in Python; the correct syntax is `sens.ChFilterAccess.FILTER_NONE`.  
    - Also, calling `SetFilter` three times in a row overwrites the previous filter; only the last one will be active. This is likely a logical error.  
    **Deduct 15 points** for incorrect API usage and logical error.

- **Robot motor speed setting:**  
  The `move` function calls `robot.SetMotorSpeed(speed, wheel_index)` twice per mode, which is correct assuming the API accepts these calls. No API misuse here.
