### 2. Correctness (30 points)

- **Use of PyChrono API**:  
  - `vehicle.SetContactMethod(contact_method)` is called before initialization, which is correct.  
  - Visualization types are set after initialization, which is acceptable.  
  - `vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)` is called after initialization, which is **not recommended**. According to best practices, collision system type should be set **before** system initialization to avoid inconsistent behavior. This could cause simulation instability or ignored settings.  
  **Deduct 15 points** for incorrect collision system setting timing.

- **Sentinel and Target Spheres**:  
  The spheres are created as `chrono.ChSphereShape()` assets and added to `chrono.ChBody()` instances, but these bodies are **not added to the system** (`sys.Add(body)`) and their positions are set incorrectly. The code sets `sentinel_sphere.Pos = path[0]` which is a property of the shape, but the shape's position is relative to the body frame. The body itself has no position set, so the spheres will not appear at the intended world positions.  
  Correct approach: set the body's position (`sentinel_body.SetPos(path[0])`) and then add the visual asset.  
  **Deduct 10 points** for logical error in visualization asset positioning and missing system addition.

- **Driver Inputs**:  
  The call `driver.GetInputs(path)` is unusual. The typical API is `driver.GetInputs()` without arguments; the path is usually set during driver initialization or via other methods. This might be a misuse or misunderstanding of the API. However, since the driver is a `ChPathFollowerDriver`, it may accept a path argument, but this is not standard in the documented API.  
  **Deduct 5 points** for minor API misuse or unclear usage.

- **Use of `chrono.QUNIT`**:  
  Used correctly for identity quaternion.

- **Use of `vis.AddAsset()`**:  
  The visualization system does not have an `AddAsset()` method according to the documentation; assets are usually added to bodies or the system. This is likely an incorrect API call.  
  **Deduct 15 points** for incorrect API usage that could cause runtime errors or no effect.

- **Use of `vehicle.GetVehicle()` vs `vehicle`**:  
  The code uses `vehicle.GetVehicle()` when passing to `ChWheeledVehicleVisualSystemIrrlicht.AttachVehicle()` and driver initialization. This is correct as `vehicle` is a wrapper and `GetVehicle()` returns the underlying vehicle object.
