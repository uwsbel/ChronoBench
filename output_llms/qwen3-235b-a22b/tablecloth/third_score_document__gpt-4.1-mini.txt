- **Elements:** Two `ChElementShellBST` elements are created per cell, with nodes set correctly. However, the setting of boundary nodes for the elements is suspicious:

  - The `SetNodes` method for `ChElementShellBST` expects 6 nodes: the 3 corner nodes of the triangle and 3 "boundary" nodes for curvature or bending. The code attempts to assign these boundary nodes but the logic is inconsistent and may cause indexing errors or incorrect node assignments at edges.

  - For example, in the first element (`melementA`), the boundary nodes are:
    ```python
    boundary_1 = mynodes[(iz + 1) * (nsections_x + 1) + ix + 1]
    boundary_2 = mynodes[(iz + 1) * (nsections_x + 1) + ix - 1] if ix > 0 else mynodes[(iz + 1) * (nsections_x + 1) + ix]
    boundary_3 = mynodes[(iz - 1) * (nsections_x + 1) + ix + 1] if iz > 0 else mynodes[(iz) * (nsections_x + 1) + ix + 1]
    ```
    - When `ix == 0`, `boundary_2` is assigned to the same node as `boundary_1` (since `ix - 1` would be -1, so fallback to `ix`).
    - When `iz == 0`, `boundary_3` is assigned to the node at `(iz) * (nsections_x + 1) + ix + 1`, which is the same as one of the corner nodes.
    - This may cause degenerate or incorrect element definitions on boundaries.

  - Similarly for `melementB`, the boundary nodes are assigned with similar fallback logic.

  - While this may not cause a crash, it is not the best practice and could lead to incorrect element behavior or simulation inaccuracies.
