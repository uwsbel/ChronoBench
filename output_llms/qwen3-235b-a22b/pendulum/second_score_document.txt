  The ground is added with `sys.Add(ground)` and pendulum with `sys.AddBody(pend_1)`. According to the API, `AddBody()` is the standard method to add bodies. `Add()` is a more generic method but still works. This inconsistency is minor but not incorrect. No deduction.

- **Use of `chrono.ChVisualShapeCylinder(radius, height)`:**  
  The constructor takes radius and height, used correctly.

- **Use of `chrono.ChFramed`:**  
  The code uses `chrono.ChFramed` for positioning visual shapes and initializing the joint. The API documentation and examples use `chrono.ChCoordsys` or `chrono.ChCoordsysD` for frames (position + rotation). `ChFramed` is not a standard documented class in PyChrono. This is a significant issue because it may cause runtime errors or unexpected behavior.

- **Joint initialization:**  
  The spherical joint is initialized with `spherical_joint.Initialize(ground, pend_1, chrono.ChFramed(...))`. The API requires a `chrono.ChCoordsys` or `chrono.ChCoordsysD` object for the frame parameter. Using `ChFramed` is incorrect and likely to cause errors.

  `spherical_joint.AddVisualShape(sphere_joint)` is called. According to the API, joints do not typically have visual shapes added this way. Visual shapes are usually added to bodies. This is a misuse of the API and may have no effect or cause errors.

- **Setting initial angular velocity:**  
  `pend_1.SetWvel_par(chrono.ChVector3d(0, 0, 2))` is correct.

- **Logging:**  
  The logging prints position and velocity components correctly.

- **Incorrect use of `chrono.ChFramed` instead of `chrono.ChCoordsys` or `chrono.ChCoordsysD` for joint initialization and visual shape positioning:** -15 points (significant API misuse).

- **Adding visual shape to joint (likely ineffective or incorrect):** -10 points (logical error).
