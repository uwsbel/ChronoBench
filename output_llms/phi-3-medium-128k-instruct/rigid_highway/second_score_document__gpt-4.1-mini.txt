### 2. Correctness (30 points)

- **Use of Vehicle API:**  
  The vehicle is created and initialized correctly with proper parameters.

- **Collision System Type:**  
  The collision system type is set **after** vehicle initialization:  
  ```python
  vehicle.GetSystem().SetCollisionSystemType(chrono.ChCollisionSystem.Type_BULLET)
  ```  
  According to best practices, the collision system type should be set **before** initializing the vehicle to ensure proper collision system setup. Setting it after initialization may have no effect or cause inconsistent behavior.  
  **Deduct 15 points** for this significant API misuse.

- **Terrain Patch Creation:**  
  The initial terrain patch is created correctly with a mesh for collision and visualization.

- **Adding Bump Patch Inside Simulation Loop:**  
  The bump patch is created and added inside the simulation loop at every iteration:  
  ```python
  bump_mesh = chrono.ChTriangleMeshConnected().CreateFromWavefrontFile(...)
  bump_vis_mesh = chrono.ChTriangleMeshConnected().CreateFromWavefrontFile(...)
  bump_vis_shape = chrono.ChVisualShapeTriangleMesh()
  ...
  bump_patch = terrain.AddPatch(...)
  bump_patch.GetGroundBody().AddVisualShape(bump_vis_shape)
  ```  
  This is a **major logical error**: adding a patch every time step will cause memory leaks, performance degradation, and incorrect simulation behavior. Terrain patches should be added once during initialization, not repeatedly.  
  **Deduct 15 points** for this logical error.

- **Advancing Driver, Terrain, Vehicle, and Visualization Twice per Loop:**  
  The script calls `Advance(step_size)` on driver, terrain, vehicle, and vis twice per loop iteration: once before adding the bump patch and once after. This is redundant and incorrect.  
  **Deduct 10 points** for this logical error.

  This line is redundant since it sets the data path to itself. No effect but unnecessary.
