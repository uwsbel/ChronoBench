### 2. Correctness (30 points)

- **Use of `ChContactMaterialNSC` in `ChBodyEasySphere`:** The constructor expects a material pointer, but `ChContactMaterialNSC` is not a shape material but a contact material. The `ChBodyEasySphere` expects a `ChMaterialSurface` or similar. The code passes `sphere_mat` (a `ChContactMaterialNSC`), which is incorrect. The correct approach is to create a `ChMaterialSurfaceNSC` and assign it to the body. This is a significant API misuse.

- **`SetUseGyroTorque(False)`** is correctly used to disable gyroscopic torque.

- **Gravity is set to zero:** This is intentional, as gravity is replaced by custom gravitational attraction forces. This is acceptable.

- **Energy calculation:** The kinetic energy calculation uses `body.GetVelocity().Length2()`, which returns the squared length of velocity vector, so kinetic energy is correctly computed as 0.5 * m * v².

- **Potential energy and force calculation:** The gravitational force is computed pairwise with Newton's law, and forces are applied correctly with `AccumulateForce`. This is logically correct.

- **Solver setup:** PSOR solver with 40 iterations is set, which is appropriate.

- **Collision system:** Bullet collision system is set correctly.

- **`emitter.SetParticlePositioner(chrono.ChRandomParticlePositionOnGeometry())`** is used with `SetGeometry(chrono.ChBox(50, 50, 50), chrono.ChFramed())`. However, `chrono.ChBox` is a shape, but `ChRandomParticlePositionOnGeometry.SetGeometry()` expects a geometry object. This usage is acceptable as per API.

- **`sys.GetCollisionSystem()` is used to get collision system and passed to the callback for binding.** This is correct.

**Deductions:**

- 15 points for incorrect use of `ChContactMaterialNSC` as a material in `ChBodyEasySphere`.
