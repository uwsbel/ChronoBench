### 2. Correctness (30 points)

**Major issues:**

- **Custom force functor `Evaluate` method:**

  - The calculation of `delta` is incorrect:

    ```python
    delta = frame2.GetPos() + frame2.TransformPoint(pointB) - frame1.GetPos() - frame1.TransformPoint(pointA)
    ```

    According to PyChrono API and physics, the relative vector between two points attached to two frames is:

    ```python
    delta = (frame2.GetPos() + frame2.TransformPoint(pointB)) - (frame1.GetPos() + frame1.TransformPoint(pointA))
    ```

    The code as written subtracts `frame1.GetPos()` and then subtracts `frame1.TransformPoint(pointA)`, which is equivalent to:

    ```python
    frame2.GetPos() + frame2.TransformPoint(pointB) - frame1.GetPos() - frame1.TransformPoint(pointA)
    ```

    This is mathematically the same as the correct expression, so no error here.

  - However, the calculation of `rel_speed` is problematic:

    ```python
    rel_speed = frame2.GetPosDT() + frame2.TransformVector(frame2.GetPosDF() + frame2.GetFrameVec() % frame2.TransformPoint(pointB)) - frame1.GetPosDT() - frame1.TransformVector(frame1.GetPosDF() + frame1.GetFrameVec() % frame1.TransformPoint(pointA))
    ```

    This expression is suspicious because:

    - `GetPosDF()` is not a standard method in PyChrono frames (the API documentation does not mention it).
    - `GetFrameVec()` is not a standard method.
    - The use of `%` operator for vector cross product is not standard Python or PyChrono; PyChrono uses `.Cross()` or `.Cross()` method for cross product.
    - The relative velocity of two points attached to frames should be computed as:

      ```python
      vA = frame1.GetPosDT() + frame1.TransformVector(frame1.GetWvel_par()) + frame1.GetWvel_loc().Cross(pointA)
      vB = frame2.GetPosDT() + frame2.TransformVector(frame2.GetWvel_par()) + frame2.GetWvel_loc().Cross(pointB)
      rel_speed = vB - vA
      ```

    The code uses non-existent methods and operators, which would cause runtime errors or incorrect behavior.

- **Use of `spring_2.EnableSpringing(chrono.ChLinkPointPoint.SpringType_NONE)`**

  - According to the API, `EnableSpringing` expects a spring type enum, but `SpringType_NONE` disables springing. Since the goal is to add a custom force functor, disabling springing is logical, but then the next line:

    ```python
    spring_2.AddForce(chrono.ChFramed(chrono.ChVector3d(0, 0, 0), chrono.ChVector3d(0, 0, 0)), force_functor)
    ```

    is problematic because `AddForce` is not a documented method of `ChLinkPointPoint`. The API documentation does not mention `AddForce` for links; forces are usually applied to bodies or via force functors attached to links that support them (like `ChLinkTSDA`).

    This likely will cause an error or have no effect.
