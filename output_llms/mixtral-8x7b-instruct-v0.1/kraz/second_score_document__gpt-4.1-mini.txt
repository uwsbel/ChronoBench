### 2. Correctness (30 points)

- **Use of `vehicle.GetTractor()` vs `vehicle`**:  
  The code inconsistently uses `vehicle` and `vehicle.GetTractor()`. For example, `vehicle.SetChassisVisualizationType(...)` is called on `vehicle`, but `vis.AttachVehicle(vehicle.GetTractor())` is used for visualization attachment, and `print("VEHICLE MASS:", vehicle.GetTractor().GetMass())` is called.  
  According to the PyChrono vehicle API, `veh.Kraz()` returns a vehicle object, and `GetTractor()` returns the underlying vehicle chassis or tractor object. This is somewhat confusing and inconsistent. It would be better to use one consistently or clarify the difference.  
  **Minor inaccuracy: -5 points**

- **Initialization of Visualization Types**:  
  The method `vehicle.SetChassisVisualizationType(vis_type, vis_type)` is called with two arguments, but the API documentation for `SetChassisVisualizationType` typically takes a single argument (e.g., `vis_type`). The same applies to `SetSuspensionVisualizationType(vis_type, vis_type)`, `SetWheelVisualizationType(vis_type, vis_type)`, and `SetTireVisualizationType(vis_type, vis_type)`.  
  This suggests a misunderstanding of the API or an incorrect call signature.  
  **Significant incorrect API usage: -15 points**

- **Driver Steering Logic**:  
  The double lane change logic is implemented inside the simulation loop but the steering commands are set after the synchronization and advancement steps. This means the steering commands will only take effect in the next iteration, which is acceptable but could be clearer. No major logical error here.  
  **No deduction.**

- **Use of `chrono.SetChronoDataPath(chrono.GetChronoDataPath())`**:  
  This line sets the data path to itself, which is redundant and unnecessary. The data path should be set once, ideally to a specific directory.  
  **Minor inaccuracy: -5 points**

- **Use of `driver.GetInputs()` before `driver.Synchronize()`**:  
  The code calls `driver.GetInputs()` before `driver.Synchronize(time)`. According to best practices, inputs should be updated after synchronization to get the latest driver inputs. This is a minor logical ordering issue.  
  **Minor logical error: -10 points**

- **Use of `vehicle.GetSystem().SetCollisionSystemType(...)` after vehicle initialization**:  
  Setting the collision system type after vehicle initialization may not have the intended effect because the system might have already initialized collision settings. It is better to set collision system type before initialization.  
  **Minor incorrect API usage: -10 points**

**Total Correctness deduction: 45 points (exceeds max 30, cap at 30)**
