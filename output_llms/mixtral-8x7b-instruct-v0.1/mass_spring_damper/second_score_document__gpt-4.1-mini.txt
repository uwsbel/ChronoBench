### 2. Correctness (30 points)

- **ForceFunctor Implementation:**  
  - The custom `MySpringForce` class inherits from `chrono.ForceFunctor` and overrides `AddForce`.  
  - The method signature is `AddForce(self, body, pt, inv_mass, inv_damp)`. According to PyChrono API, `AddForce` should have signature `(self, body, pt, inv_mass, inv_damp)`. This matches.  
  - The force calculation logic is flawed:
    - `rel_pos = body.TransformPointLocalToParent(pt)` is correct to get the point in global coordinates.
    - `dist = rel_pos.Length()` is the distance from the origin to the point in global coordinates.
    - The spring force is applied only if `dist > rest_length`.
    - The force vector is computed as `-self.spring_coef * diff`, where `diff` is the vector from rest length along the direction.
    - The damping force calculation is incorrect:
      - `vel = body.TransformDirectionLocalToParent(diff / dist) * body.GetPos_dt()` is invalid because `body.GetPos_dt()` returns a `ChVectorD` (velocity), and multiplying two vectors directly is not defined.
      - The damping force should be proportional to the relative velocity along the spring direction, but this code attempts to multiply a vector by another vector, which is not a valid operation.
    - The use of `inv_damp` in damping force is unclear and likely incorrect.
    - The force is added to the body via `body.AddForce(force)`, which is correct.

- **Spring Initialization:**  
  - `spring_1` is a `ChLinkTSDA` initialized with `(body_1, ground, True, chrono.ChVector3d(0, 0, 0), chrono.ChVector3d(-1, 0, 0))`.  
    - The third argument `True` corresponds to `pos_are_relative` (according to typical API), which is acceptable.  
    - The two points are the attachment points in local coordinates of each body.  
    - Rest length, spring coefficient, and damping coefficient are set correctly.  
  - `spring_2` is a `ChLinkSpring` initialized with `(body_2, ground, chrono.ChVector3d(0, 0, 0), chrono.ChVector3d(1, 0, 0))`.  
    - `ChLinkSpring` does not have a `pos_are_relative` argument; this matches the documented usage.  
    - The force functor is set to the custom `MySpringForce(50, 1)`.  
  - Both springs are added to the system.

- **Body Properties:**  
  - Mass and inertia are set to 1 and `(1,1,1)` respectively, which is acceptable for a simple demo.  
  - Bodies are not fixed, ground is fixed.  
  - Collision is disabled on ground, but not explicitly enabled on dynamic bodies (default is enabled). This is acceptable.

- **Visualization:**  
  - The camera is placed at `(0, 0, 6)`, which is a reasonable viewpoint.  
  - Logo, skybox, and lights are added.

**Major correctness issue:**
