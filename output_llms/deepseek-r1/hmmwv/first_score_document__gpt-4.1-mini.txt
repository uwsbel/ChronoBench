### 2. Correctness (30 points)

- **Incorrect API usage:**  
  - The line:  
    ```python
    vehicle.GetDriverInputs() = driver_inputs
    ```  
    This is invalid Python syntax and incorrect API usage. `GetDriverInputs()` is a getter method returning a copy or reference to inputs, not a setter. The correct method to set driver inputs is usually `vehicle.SetDriverInputs(driver_inputs)` or passing inputs during `Synchronize`. According to the vehicle API, driver inputs are passed to `vehicle.Synchronize()`; setting them directly is not standard.  
    This is a **significant error** that would break the simulation or cause runtime errors.  
    **-15 points**

- **Logical errors:**  
  - The order of advancing components and calling `system.DoStepDynamics(step_size)` is not optimal. Usually, `DoStepDynamics()` is called first to advance the physics, then visualization and other components are updated. Here, `vehicle.Advance()`, `terrain.Advance()`, and `vis.Advance()` are called before `DoStepDynamics()`. This may cause synchronization issues or visual lag.  
  - However, in vehicle simulations, it is common to advance subsystems before stepping the system to update internal states. This is acceptable and not a clear error.  
  **No deduction.**

  - The `steering_time` variable is defined but only used once to compute `driver.SetSteeringDelta(0.02 / steering_time)`. This is fine but could be simplified.
