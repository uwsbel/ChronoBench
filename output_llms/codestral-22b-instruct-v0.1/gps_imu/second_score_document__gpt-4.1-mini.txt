### 2. Correctness (30 points)

- **API Usage:**  
  - `vehicle.SetContactMethod(contact_method)` is correct.  
  - `vehicle.SetChassisCollisionType(chassis_collision_type)` with `CollisionType_NONE` disables chassis collision, which is acceptable but may reduce realism. This is a design choice, not an error.  
  - Tire model and step sizes are set correctly.  
  - Terrain patch material is created with friction and restitution set properly.  
  - Visualization system uses `veh.ChWheeledVehicleVisualSystemIrrlicht()` which is correct for vehicle visualization.  
  - Sensor creation and filter pushing are done correctly.  
  - The simulation loop uses `vis.Run()` for loop control and calls `BeginScene()`, `Render()`, and `EndScene()` properly.  
  - Driver inputs are created manually each loop iteration instead of using the interactive driver’s input; this is inconsistent. The driver is created as `ChInteractiveDriverIRR(vis)` which normally handles input internally, but the code manually creates `veh.ChDriverInputs` and passes them to `vehicle.Synchronize()`. This is a logical inconsistency and could cause unexpected behavior.  
  - The `driver.Synchronize(time)` call is made but the driver inputs are not passed to the driver; instead, inputs are created separately and passed to `vehicle.Synchronize()`. This is a logical error.  
  - The `driver.Advance(step_size)` is called but since inputs are not passed through the driver, the driver is effectively unused.  
  **Deduct 10 points for logical error in driver input handling.**

- **Minor inaccuracies:**  
  - The `gps.GetMostRecentGPSBuffer().GetGPSData()` is called every `log_steps` but no check is made if data is available, which could cause issues if the buffer is empty at the start. Minor issue.  
  - The `offset_pose` uses `chrono.ChFramed` instead of `chrono.ChFrame` or `chrono.ChCoordsysd`. Minor API misuse.  
  **Deduct 5 points for minor inaccuracies.**
